# 3D Engine & Scene Pitfalls (PF-E3D)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-E3D-01 | Retired: each open of the 3D view built a fresh `Qt3DWindow`, because a hidden and re-shown one rendered blank, and the code no longer follows this since the Qt 3D window is gone. | retired | [10](../10-3d-engine-scene.md#pf-e3d-01) |  |
| PF-E3D-02 | Retired: the Qt 3D walk read keys through an event filter on the embedded `Qt3DWindow`, whose key events never reach the `QMainWindow`, and the code no longer follows this since that window is gone. | retired | [10](../10-3d-engine-scene.md#pf-e3d-02) |  |
| PF-E3D-03 | Retired: the Qt 3D walk used `QFirstPersonCameraController` for mouse-look only and moved the walker itself, because the controller free-flies, and the code no longer follows this since Qt 3D is gone. | retired | [10](../10-3d-engine-scene.md#pf-e3d-03) |  |
| PF-E3D-04 | Tooling that must run headless writes its own timestamped log, per-phase metrics and a `faulthandler` watchdog, because without timestamps a slow run and a hung run look the same. | standing | [10](../10-3d-engine-scene.md#pf-e3d-04) | 11.4.5 |
| PF-E3D-05 | Every scene-record length is snapped to 1e-7 cm and every signature match is confirmed by comparing the values, so float dust cannot invent an edit and a hash collision cannot hide one. | standing | [10](../10-3d-engine-scene.md#pf-e3d-05) | 11.4.14 |
| PF-E3D-06 | Whether a Qt Quick frame can be had is read from the frame itself, its size within half a device pixel of the window's, not inferred from Qt's window predicates, and no Python Qt message handler runs beside a shown window. | standing | [10](../10-3d-engine-scene.md#pf-e3d-06) | 11.4.15 |
| PF-E3D-07 | A memory soak takes no frame inside its measured loop, only one before and one after, and a test waits for the condition the product itself waits for, never for a guessed duration. | standing | [10](../10-3d-engine-scene.md#pf-e3d-07) | 11.4.16 |
| PF-E3D-08 | Anything that comes and goes in the 3D pane is a resize of the view, so its room is reserved, and a walk-mode key filter owns a key only if it claims it at `ShortcutOverride`. | standing | [10](../10-3d-engine-scene.md#pf-e3d-08) | 11.4.19 |
| PF-E3D-09 | Measure the unchanged code before crediting a change with a difference, and after merging into a removal scan the whole merged tree for every removed name, not only the files that conflicted. | standing | [10](../10-3d-engine-scene.md#pf-e3d-09) | 11.4.20 |
| PF-E3D-10 | Derived lifetime visibility must preserve the existing throttled 3D clock path while real plan edits still announce revisions. | standing | [10](../10-3d-engine-scene.md#pf-e3d-10) |  |
| PF-E3D-11 | A GUI-heartbeat measurement must include the time from the last tick to the end of the work, and it must run the real event loop, not `processEvents()`. | standing | [10](../10-3d-engine-scene.md#pf-e3d-11) |  |
| PF-E3D-12 | A quiet timer that fires proves the GUI thread is alive NOW, not that the scene was still for the whole quiet time; a pass after it must wait for a settle in which a repaint can restart the quiet time. | standing | [10](../10-3d-engine-scene.md#pf-e3d-12) |  |
| PF-E3D-13 | Since Qt 6.12 the engine's pick honours each material's cull mode: a `NoCulling` part is picked from behind too, a culled one only on its front faces (6.11 picked front faces of every material). A selection oracle must keep every face of the two-sided kinds (`materials.TWO_SIDED_KINDS`, pinned against the QML) and the front faces of the rest. | standing | [10](../10-3d-engine-scene.md#pf-e3d-13) |  |
| PF-E3D-14 | A Qt 6.12 `SkyMaterial` compiles its shader only once EVERY texture it samples exists: hand it texture DATA (`QQuick3DTextureData`), never a texture rendered in the frame (`QuadTextureProvider`) — a provider's texture exists only after its first render, so the first frame after the sky appears is white, and a frame rendered only once (the app's offscreen frames) is white every time. A texture input left empty never compiles, and Qt silently draws its built-in debug sky. | standing | [10](../10-3d-engine-scene.md#pf-e3d-14) |  |
| PF-E3D-15 | A custom material's sky term is compiled when `QSSG_ENABLE_LIGHT_PROBE` is set OR `SAMPLE_PROBE_GLSLLIB` is defined, never on the macro alone: under a Qt 6.12 `SkyMaterial` Qt calls the material's `IBL_PROBE()` and includes the probe samplers while it leaves `QSSG_ENABLE_LIGHT_PROBE` false, so a guard on the macro alone compiles the sky term out and the surface loses the sky's light without a warning. | standing | [10](../10-3d-engine-scene.md#pf-e3d-15) |  |
| PF-E3D-16 | On Qt 6.12 destroying an EARLIER sky Texture sets the scene environment's light probe to null although the probe already holds the current sky (the stale destroyed-watcher still fires), so the environment restores its own lightProbe binding in onLightProbeChanged, in the same signal, before any frame renders; a test of the sky must take a frame AFTER the old Textures are deleted. | standing | [10](../10-3d-engine-scene.md#pf-e3d-16) |  |
| PF-E3D-17 | A Qt 6.12.0 `SkyMaterial` never lights the scene and never draws through a cube: Qt builds and pre-filters its cube for image-based light, the Cubemap skybox mode, a reflection probe or a screen texture, and that pre-filter uses a freed QRhi resource and kills the process natively, so the atmosphere backs the view on screen (`enableIBL: false`, a ScreenSpace skybox mode) and the painted sky's texture stays the light probe under both sky models. | standing | [10](../10-3d-engine-scene.md#pf-e3d-17) |  |
| PF-E3D-18 | A picture beside a shown view comes from a second `View3D` of the same scene (`importScene`, the same camera and environment), read with `grabToImage` driven by one synchronous `grabWindow`; never a `render_records` beside a shown window, never a wait for the window's next frame, and never a `View3D` made and destroyed per picture. | standing | [10](../10-3d-engine-scene.md#pf-e3d-18) |  |
| PF-E3D-19 | With a colour table on, the environment's saturation and contrast are 1 and the table carries them: Qt applies them unclamped right before its table lookup, and that lookup is a `texelFetch` whose column a colour below 0 pushes into the neighbouring slice. Texture DATA for a table runs its rows opposite to a loaded PNG, and a `Texture`'s `flipV` does not reach an effect's sampler. | standing | [10](../10-3d-engine-scene.md#pf-e3d-19) |  |
| PF-E3D-20 | Frames for Qt's recorder are BT.709 YUV computed by the app, in an HD size: handed RGB it converts with BT.601 and writes no colour tag, and players read an untagged HD stream as BT.709. A test reads a decoded frame's Y, Cb and Cr itself; `QVideoFrame.toImage` guesses the matrix differently by platform. | standing | [10](../10-3d-engine-scene.md#pf-e3d-20) |  |
| PF-E3D-21 | With glow on, an `ExtendedSceneEnvironment` never runs two effects ahead of its own scene effect: screen-space reflections plus a depth of field (Qt's or the app's `PhotoBlur.qml`), or any two user `Effect`s, kill Qt 6.12's render thread in `d3d11.dll` (a read at address 0x16d in `OMSetRenderTargets`) or draw a wrong picture, and nothing reaches stderr or `app.log`. `Garden.qml` turns reflections off while `photoBlur > 0` (`depthOfFieldActive`). Only Ultra has reflections, so only Ultra crashed; and a probe that isolates the profile runs on the default quality, so it never saw it. | standing | [10](../10-3d-engine-scene.md#pf-e3d-21) |  |
| PF-E3D-22 | A kept render is never at a name a later run may choose to write: `Mp4Writer` takes the first free `<stem>.part[<n>].mp4`, because the finished video whose target a player held open is kept as a part file and the next recording of that name used to unlink it. | standing | [10](../10-3d-engine-scene.md#pf-e3d-22) |  |
| PF-E3D-23 | While a camera tour moves the shared sim clock, the owner's held moment - not `SimClock.plan_date` - is what every agent-facing date claim must use: `get_plan_summary`'s `as_of_date` and each object's `present`, and a newly created plant's planting date. Only a tour with a `date_range` or `time_range` holds the clock; diagnostics and a 2D render describe the frame the tour is showing and are not date claims. | standing | [10](../10-3d-engine-scene.md#pf-e3d-23) |  |
| PF-E3D-24 | A clock writer that sweeps DATES holds the UTC time of day, not the wall time: the sun is computed from `SimClock.utc`, so a wall time held across a DST change moves the sun by an hour. Use `SimClock.set_utc_time_on(day, utc_time)`, which derives the wall reading through the zone (the repeated hour's `fold` included); a local date with no exact instant (a 23-hour spring day) gets the nearest reading on that date, within the missing hour. | standing | [10](../10-3d-engine-scene.md#pf-e3d-24) |  |
| PF-E3D-25 | A capture's look must be scaled for its PICTURE HEIGHT where Qt's effect is sized in pixels: Qt samples SSAO's scene-unit radius on a pixel grid, so a 4K picture's garden band read 4.3 luma darker than 1080p with AO on and 0.0 with it off (the horizon band read 1.75; glow changed nothing). `Quick3DHost.capture` sets `captureAoDistanceScale = ao_distance_scale(height)` (1080p and smaller 1.0, 2x height 0.5, floor 0.25) for its frame and restores 1.0; tune the radius, not the strength. | standing | [10](../10-3d-engine-scene.md#pf-e3d-25) |  |
| PF-E3D-26 | Ending a camera tour's flight must invalidate the flight's IN-FLIGHT forge build, not merely re-submit the plants: if a plant's applied LOD already equals the camera's, `submit_record` queues nothing, and the flight's finer result then lands with no pending job to reject it (`pending is None`). `ForgeWorker.fly_path(None)` bumps `_epoch`, so `_step_background` drops a completion that started under the flight. | standing | [10](../10-3d-engine-scene.md#pf-e3d-26) |  |
| PF-E3D-27 | A post effect that sorts pixels into depth layers counts a layer's SILHOUETTE pixel for a fraction only: the colour is multisampled (partly the thing beside it) while the depth pass takes one sample and puts all of it in the layer. `photoblur_layer.frag` weighs a pixel whose cross neighbour lies outside its layer by `SILHOUETTE_WEIGHT` (0.2). | standing | [10](../10-3d-engine-scene.md#pf-e3d-27) |  |
| PF-E3D-28 | Judge an ambient-occlusion change at more than one picture size and on a far camera before shipping it: Qt 6.12's pass leaves the self-occlusion its bias does not remove in a RING of open ground whose distance moves with the picture's height (its sample radius is a world radius on a pixel grid). A view-sized pane and a 1080p or 4K save of the same camera then differ by band, not by a uniform offset, and a mean hides it. | standing | [10](../10-3d-engine-scene.md#pf-e3d-28) |  |
| PF-E3D-29 | A picture taken from another camera than the view's — a tour's frame, an agent's `render_3d_view` with a camera — is lit by the garden lights nearest ITS target: `WorkspaceCaptureCoordinator` calls `aim_lamps(target)` before the capture and `aim_lamps(None)` after it (a tour: when it ends); the lamp slots are a camera-dependent choice like the precipitation's box, never the pane's. | standing | [10](../10-3d-engine-scene.md#pf-e3d-29) |  |
