# Persistence, Undo & Layers Pitfalls (PF-PER)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-PER-01 | Clipboard copy and paste go through the one `ProjectManager` serializer that save and load use, because a second serializer for the same vocabulary drifts and silently loses data. | standing | [03](../03-persistence-undo-layers.md#pf-per-01) |  |
| PF-PER-02 | A failed plan load must leave no partial scene behind a stale file path: deserialize in memory first, clear `_current_file` on failure, and keep the autosave until the new plan loads. | pointer | [03](../03-persistence-undo-layers.md#pf-per-02) |  |
| PF-PER-03 | A missing or undecodable background image loads as a placeholder that saves its original data back, so a momentarily unreadable asset is never dropped on the next save. | pointer | [03](../03-persistence-undo-layers.md#pf-per-03) |  |
| PF-PER-04 | `CommandManager.command_executed` fires only on `execute()`, so dimension line updates also connect to `can_undo_changed` and `can_redo_changed` to follow undo and redo. | standing | [03](../03-persistence-undo-layers.md#pf-per-04) |  |
| PF-PER-05 | Retired: every attach site used to lift a plant above its bed with an explicit `ensure_z_above_parent` z bump, and the code no longer writes z, deriving it from persisted stacking ranks instead. | retired | [03](../03-persistence-undo-layers.md#pf-per-05) |  |
| PF-PER-06 | A CSV meant for Excel is written as `utf-8-sig`, because Excel on Windows reads UTF-8 without a BOM as Latin-1 and garbles umlauts. | standing | [03](../03-persistence-undo-layers.md#pf-per-06) |  |
| PF-PER-07 | A panel that changes model state a derived overlay reads must also reach `scene.changed` or `stack_changed`, for example via `item.update()`, because `mark_dirty()` alone never repaints. | standing | [03](../03-persistence-undo-layers.md#pf-per-07) |  |
| PF-PER-08 | The layers panel is a pure view that never mutates `Layer` objects or its own list; every layer change goes from a request signal through an undoable command in `core/commands.py`. | standing | [03](../03-persistence-undo-layers.md#pf-per-08) |  |
| PF-PER-09 | An undoable command revalidates its mutable preconditions, such as a replacement layer's lock, immediately before every mutation including redo, not only in its constructor. | standing | [03](../03-persistence-undo-layers.md#pf-per-09) |  |
| PF-PER-10 | Only `execute()` and `register_applied()` put a command on the undo stack, both emitting the full signal set, and undo and redo emit `stack_changed` so every change dirties the document. | standing | [03](../03-persistence-undo-layers.md#pf-per-10) |  |
| PF-PER-11 | Every `ResizeItemCommand` caller, including each `partner_resizes` applier, uses the one apply function in `ui/canvas/geometry_apply.py`, and its tests run over non-zero rotations where drift shows. | standing | [03](../03-persistence-undo-layers.md#pf-per-11) |  |
| PF-PER-12 | The serializer writes scene objects bottom to top with `reversed(scene.items())`, because `scene.items()` is top-first and a load re-adds objects bottom-up in file order. | standing | [03](../03-persistence-undo-layers.md#pf-per-12) |  |
| PF-PER-13 | A pasted or duplicated item takes its source's `layer_id` when that layer still resolves in the target scene, else the active layer, so it never lands silently layer-less. | standing | [03](../03-persistence-undo-layers.md#pf-per-13) |  |
| PF-PER-14 | A refresh that runs opportunistically between a command's `execute()` and `undo()` derives its output and never writes the state an undo snapshot depends on. | standing | [03](../03-persistence-undo-layers.md#pf-per-14) |  |
| PF-PER-15 | A same-scene load clears items through one serialized-document-item predicate, and a UUID delete refuses duplicate live IDs and confirms the target is gone before reporting success. | standing | [03](../03-persistence-undo-layers.md#pf-per-15) |  |
| PF-PER-16 | A finite float is not a safe Qt geometry input: bound it at the creation boundary, treat an explicit null as a refusal rather than an omission, and test hostile input through the real transport. | standing | [03](../03-persistence-undo-layers.md#pf-per-16) |  |
| PF-PER-17 | A date editor shows stored dates as they are, and an override whose end precedes its start is ignored on read and refused on write, never rewritten in the file. | standing | [03](../03-persistence-undo-layers.md#pf-per-17) |  |
| PF-PER-18 | Numeric, download and settings checks sit at the shared ingestion and persistence boundaries, and geometry is validated on Qt's derived bounds and spans, not only on each finite operand. | standing | [03](../03-persistence-undo-layers.md#pf-per-18) |  |
| PF-PER-19 | Authored examples use creation commands and draw plants above raised parents. | standing | [03](../03-persistence-undo-layers.md#pf-per-19) | |
| PF-PER-20 | A shape is serialized in its **parent's** frame - the local geometry translated by `mapToParent(shape centre) - shape centre` - not by `item.pos()`, because `QGraphicsItemGroup.addToGroup()` folds the old rotation pivot into `pos()`. | standing | [03](../03-persistence-undo-layers.md#pf-per-20) |  |
| PF-PER-21 | A command that replaces a shape with a rebuilt one gives the replacement the source's UUID and garden bookkeeping (name, metadata copy, parent/child links, layer, label flags, transform). A constructor's fresh UUID silently orphans everything keyed by the old one. | standing | [03](../03-persistence-undo-layers.md#pf-per-21) |  |
