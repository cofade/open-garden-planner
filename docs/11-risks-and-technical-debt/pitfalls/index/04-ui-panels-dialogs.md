# UI Panels, Dialogs & Forms Pitfalls (PF-UI)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-UI-01 | A connectivity health check requests the smallest page the API allows and reports bad credentials only for missing keys or an HTTP 401 or 403; timeouts and other failures raise `PlantAPIError`. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-01) |  |
| PF-UI-02 | State-dependent, variable-width widgets stay out of a `QToolBar`'s flow; transient sun-sim hints go on the status bar so the toolbar's width never changes with sun state. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-02) |  |
| PF-UI-03 | A sidebar list that drives canvas selection stores item ids, resolves the live item at click time, defers selection until the list click completes, and skips a rebuild when its rows are unchanged. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-03) |  |
| PF-UI-04 | A `QComboBox` bound to an enum with an `UNKNOWN` member includes a neutral entry for it, so missing data never displays or saves back as the index-0 concrete value. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-04) |  |
| PF-UI-05 | A context-menu action added to one bed-shape class must also reach the other three (`RectangleItem`, `PolygonItem`, `EllipseItem`, `CircleItem`), since each class implements its own menu. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-05) |  |
| PF-UI-06 | In a dialog whose Entry and History tabs share one OK button, entry-tab validation runs only while the Entry tab is active (`self._tabs.currentIndex() == 0`). | standing | [04](../04-ui-panels-dialogs.md#pf-ui-06) |  |
| PF-UI-07 | After an Entry/History tab dialog is accepted, the caller adds a new record only when the dialog's `has_new_entry` is set, since History-tab edits are already committed inside the dialog. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-07) |  |
| PF-UI-08 | A callable assigned over a widget's `mousePressEvent` returns `None`; a lambda that forwards the bool from `QDesktopServices.openUrl()` makes PyQt6 raise a `TypeError`. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-08) |  |
| PF-UI-09 | Code that needs the active theme's colours calls `ThemeColors.get_colors(get_settings().theme_mode)`; only `theme.py` passes `ThemeMode.SYSTEM`, which probes the OS palette instead. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-09) |  |
| PF-UI-10 | Bed-only context-menu actions are built and dispatched centrally through `GardenItemMixin.build_bed_context_menu` and `dispatch_bed_action`, never hand-coded into each bed shape class. | pointer | [04](../04-ui-panels-dialogs.md#pf-ui-10) |  |
| PF-UI-11 | A `QLineEdit` hosted in a `QGraphicsView` viewport accepts Return and Enter itself, since `QLineEdit` ignores them and the key would reach the canvas and finalize the active tool. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-11) |  |
| PF-UI-12 | The Dynamic Input overlay freezes in place while either field holds text, judged by buffer content rather than focus, so the user can reach it; it resumes tracking once the fields clear. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-12) |  |
| PF-UI-13 | `PropertiesPanel` rebuilds its form only when the selection's structural identity changes; otherwise registered refreshers push model values into the live widgets. Focused text editors retain edit protection; committed checkbox/dropdown/color choices must refresh on undo/redo even while focused. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-13) |  |
| PF-UI-14 | A free-text property field applies text live without a command and commits one command on a debounce or focus-out, with pending commits flushed before any form rebuild. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-14) |  |
| PF-UI-15 | Chrome icon SVGs render only through the `ui/icons.py` provider, which substitutes theme colours first, because a direct `QSvgRenderer` call paints `currentColor` black. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-15) |  |
| PF-UI-16 | A notification that must outlive a modal dialog uses a persistent dismissible bar, never `statusBar().showMessage()`, and post-open feedback is deferred until the modal has closed. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-16) |  |
| PF-UI-17 | Every `QToolBar` added to the main window gets a unique, stable, untranslated `objectName` before `addToolBar()`, because `saveState()` keys toolbars by name and empty names alias by position. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-17) |  |
| PF-UI-18 | Core toolbars are never user-hideable: `createPopupMenu()` returns `None`; startup retains application-defined toolbar rows and enforces permanent/feature visibility. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-18) |  |
| PF-UI-19 | Pixels leave the embedded Google map only through the widget grab and metadata only through the QWebChannel bridge; DOM-side tile extraction taints the canvas and leaks the API key. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-19) |  |
| PF-UI-20 | A live-verification harness hooks a dialog's accept or its `finished` signal, never a polling timer, because `QDialog.accept()` hides the window and can end the app before the next poll. | pointer | [04](../04-ui-panels-dialogs.md#pf-ui-20) |  |
| PF-UI-21 | Repairing a silently dead code path publishes everything it was suppressing, so enumerate that content and confirm it is fit to publish, such as translated, before reviving the path. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-21) | 11.4.6 |
| PF-UI-22 | Measure translated control-group size hints at narrow widths and high DPI before accepting adaptive toolbar packing. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-22) |  |
| PF-UI-23 | Calendar-only lifetime selectors ignore wheel edits and bound new choices to the shared clock range while preserving legacy metadata. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-23) |  |
| PF-UI-24 | Every property the Properties panel edits is one undoable command; a direct write into the item is neither undoable nor a mark of a modified plan. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-24) |  |
| PF-UI-25 | A Shift+click on a canvas object toggles the first selectable item under the cursor; interactive handles retain Qt mouse delivery. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-25) |  |
| PF-UI-26 | Chronological field stepping must enable cross-field steps and emit one full naive wall reading across a carry. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-26) |  |
| PF-UI-27 | A bundled overlay that prioritises the database over the plan silently discards form edits; spin gestures coalesce into the pending command and history refreshes outrank focus guards. | standing | [04](../04-ui-panels-dialogs.md#pf-ui-27) |  |
