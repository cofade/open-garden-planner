# CI, Release & Supply Chain Pitfalls (PF-CI)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-CI-01 | Third-party attribution for the frozen build comes from the files PyInstaller actually collected, mapped through wheel RECORDs including vendored copies, not from declared dependencies. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-01) |  |
| PF-CI-02 | Build inputs read the project's own dependencies from `pyproject.toml` and walk only third parties through installed metadata, because a stale `*.egg-info` on `sys.path` can shadow the project. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-02) |  |
| PF-CI-03 | A packaged build resolves the Google Maps key from Preferences first, then the environment or a `.env` beside the executable, and never bundles, serializes, logs or auto-copies the secret. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-03) |  |
| PF-CI-04 | In a windowed frozen exe `sys.stdout` can be `None`, so uvicorn starts with `log_config=None`, and the frozen `--selftest` runs detached so no inherited stdout handle masks a regression. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-04) |  |
| PF-CI-05 | The release job skips commits whose message starts with `chore:`, so version-sync chore pushes cannot start a release that computes a stale version while the new tag is still building. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-05) |  |
| PF-CI-06 | Retired: `PyQt6-3D-Qt6` had to be pinned to the exact `PyQt6-Qt6` micro version, with all four Qt wheels moving together, and the code no longer follows this rule. | retired | [06](../06-ci-release-supply-chain.md#pf-ci-06) |  |
| PF-CI-07 | File dialogs default to the open project's folder or `<Documents>/Open Garden Planner`, never the working directory, and the uninstaller copies `.ogp` files out of `$INSTDIR` before removing it. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-07) |  |
| PF-CI-08 | Retired: a non-critical CI job that has never run green is deleted or repaired, never tolerated or muted with `continue-on-error`, and the workflow it concerned no longer exists. | retired | [06](../06-ci-release-supply-chain.md#pf-ci-08) |  |
| PF-CI-09 | A version-only `pyproject.toml` edit makes `uv.lock` stale, so the version-sync chore refreshes the lock's project version offline together with both source version declarations. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-09) |  |
| PF-CI-10 | Release version bump derives from the triggering merge commit SHA (via `scripts/resolve_release_pr.py` with commit pulls lookup, squash subject `(#N)` fallback, and exact label matching), never from `gh pr list --state merged` which sorts by creation date and ignores older-created PRs. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-10) |  |
| PF-CI-11 | Windows executables, installers, and desktop shortcuts require multi-resolution `.ico` files containing all standard frames (16x16 to 256x256), and `SetCurrentProcessExplicitAppUserModelID` must be called before any GUI or WebEngine subsystem imports; an icon with only 16x16 leaves the Windows taskbar with a generic blank window icon. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-11) |  |
| PF-CI-12 | The required `Dependencies` job audits against a live advisory database, so it can turn `master` red with no code change; answer with a targeted `uv lock --upgrade-package` per named package (never a full upgrade), and let CI waive only the advisories named in the governance test's `WAIVERS` and justified in §11.2. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-12) |  |
| PF-CI-13 | A local frozen build must compare the build venv with `pylock.toml` and warn (strictly fail on request) when it holds a distribution the lock no longer pins. Removing a pin does not uninstall the package, and PyInstaller's hooks can collect its files even when the application never imports it. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-13) |  |
| PF-CI-14 | The project license is a PEP 639 SPDX expression (`license = "GPL-3.0-or-later"`) plus `license-files = ["LICENSE"]`, with no `License ::` classifier, and the build floor is `setuptools>=77`. An isolated build (`[build-system] requires`) floats, so the build group's pin alone does not protect it. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-14) |  |
| PF-CI-15 | `_version.py` is a build artifact, not source: `build_installer.py` writes it before PyInstaller and removes it afterwards, and the path is gitignored. A direct `python -m PyInstaller installer/ogp.spec` build has no such file, and the frozen app must fall back to `open_garden_planner.__version__`. The read is DYNAMIC, so PyInstaller cannot discover it: the spec lists `open_garden_planner._version` as a hidden import only when the file exists, or a release exe would report the previous synced version. A tracked or left-behind stale file lets a green build show the wrong version in About. | standing | [06](../06-ci-release-supply-chain.md#pf-ci-15) |  |
| PF-CI-16 | A required coverage check must require every measurement to succeed and combine every explicitly named partition, including serial perf coverage; failed, skipped or missing inputs must fail the check. | pointer | [06](../06-ci-release-supply-chain.md#pf-ci-16) |  |
