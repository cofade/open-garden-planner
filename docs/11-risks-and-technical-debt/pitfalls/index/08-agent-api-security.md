# Agent API & Security Pitfalls (PF-API)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-API-01 | A CLI's success output is sanitised like its failure output before a label shows it, removing every ANSI escape, not only SGR, and the box glyphs that survive escape removal. | standing | [08](../08-agent-api-security.md#pf-api-01) |  |
| PF-API-02 | A capability probe is tri-state, and an indeterminate answer never selects the more dangerous option: only a definitive absence of the flag may choose the legacy argv that fails silently. | standing | [08](../08-agent-api-security.md#pf-api-02) |  |
| PF-API-03 | An empty or effectively empty config file is recognised before parsing, under the strict policy too, while one byte of junk still fails closed, because empty and unparseable are different failures. | standing | [08](../08-agent-api-security.md#pf-api-03) |  |
| PF-API-04 | A refusal of a case that can be handled is a capability removal, so whenever a guard changes the UI, check what it still offers, since a control demoted to a manual snippet is reported as missing. | standing | [08](../08-agent-api-security.md#pf-api-04) |  |
| PF-API-05 | A CLI's capability is verified by probing the resolved binary's own help for each required flag, not its documented interface, as `PATH` may resolve another version a `shutil.which` stub never shows. | pointer | [08](../08-agent-api-security.md#pf-api-05) |  |
| PF-API-06 | A refusal leaves the filesystem exactly as found, so the backup is taken only once a write is certain, tests assert the whole directory listing, and a backup that is made is reported to the user. | pointer | [08](../08-agent-api-security.md#pf-api-06) |  |
| PF-API-07 | A parse error and a shape error get different policies: a readable file whose container key has the wrong type fails closed whatever its ownership, because replacing it discards the user's data. | pointer | [08](../08-agent-api-security.md#pf-api-07) |  |
| PF-API-08 | A best-effort reader of untrusted input catches `Exception` once at the ingestion chokepoint and never enumerates exception families, because any family left out, such as `RecursionError`, escapes. | pointer | [08](../08-agent-api-security.md#pf-api-08) |  |
| PF-API-09 | A flag that gates a destructive operation is enforced at the seam, inside the merge itself, because a check placed only at the call sites its author thought of is bypassed by every other path. | pointer | [08](../08-agent-api-security.md#pf-api-09) |  |
| PF-API-10 | A required field on a dataclass such as `AgentProviders` is a contract with every constructor, including the providers `--selftest` builds, so an extension is checked by `--selftest`, not only pytest. | standing | [08](../08-agent-api-security.md#pf-api-10) |  |
| PF-API-11 | A tool's declared return model is part of its contract, so a test calls the tool itself over the wire, not only its provider, because the model is constructed only between the two. | standing | [08](../08-agent-api-security.md#pf-api-11) |  |
| PF-API-12 | A fail-closed merge is safe only while its reader understands the real format, so JSONC gets a tolerant character-scanning reader scoped to that format, and the strict JSON reader still raises. | pointer | [08](../08-agent-api-security.md#pf-api-12) |  |
| PF-API-13 | A file the app does not own is never re-serialised: a foreign config is parsed read-only and only the affected table's line span is rewritten, so the user's comments and formatting survive. | pointer | [08](../08-agent-api-security.md#pf-api-13) |  |
| PF-API-14 | A CLI's default scope can silently write a project config into the user's working directory, so its flags are verified by running `--help` and each load-bearing scope flag is asserted in the argv. | standing | [08](../08-agent-api-security.md#pf-api-14) |  |
| PF-API-15 | Code ingesting untrusted files catches `Exception` once at the ingestion seam and logs and skips, while trusted bundled input keeps narrow typed catches so packaging bugs still fail loudly. | standing | [08](../08-agent-api-security.md#pf-api-15) |  |
| PF-API-16 | Agent API descriptions state the CAD Y-up frame, origin bottom-left with +x east and +y north so a negative dy moves south, and the prose is corrected rather than `dy` negated in a tool. | standing | [08](../08-agent-api-security.md#pf-api-16) |  |
| PF-API-17 | Agent creation feeds a Qt-free validated dict to the loader, `ProjectManager._deserialize_item_core`, inside one undo command, and is tested through create, read, save, load and read again. | standing | [08](../08-agent-api-security.md#pf-api-17) |  |
| PF-API-18 | A geometry API reads live scene-space vertices through `mapToScene`, refuses an unchanged request as a no-op, and refuses any geometry write to a constrained item rather than half-run the solver. | standing | [08](../08-agent-api-security.md#pf-api-18) |  |
| PF-API-19 | A guard sits at the trust boundary or key space, not where the code is: catch broadly and validate the field relied on, derive keys directly, and report a mismatched requested year as a miss. | standing | [08](../08-agent-api-security.md#pf-api-19) | 11.4.1 |
| PF-API-20 | An agent wrapper is tested against the engine, not literals from the issue text, because a fall-through default, a name copied from prose or an invisible hierarchy yields a plausible wrong value. | standing | [08](../08-agent-api-security.md#pf-api-20) | 11.4.3 |
| PF-API-21 | Agent tools are tested as public MCP calls on the production provider graph, and each answer uses the GUI's own generators, selected record and UI language across the whole requested period. | standing | [08](../08-agent-api-security.md#pf-api-21) | 11.4.4 |
| PF-API-22 | A security property the product relies on is set explicitly, `TransportSecuritySettings` naming the bound port and no wildcard, and asserted on that object, as a library default can mask its removal. | standing | [08](../08-agent-api-security.md#pf-api-22) |  |
| PF-API-23 | Cancellation and abandoned queued export calls must prevent later writes and release animation leases exactly once on Qt. | standing | [08](../08-agent-api-security.md#pf-api-23) |  |
