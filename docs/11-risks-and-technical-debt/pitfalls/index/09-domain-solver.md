# Domain Data & Solver Pitfalls (PF-DOM)

| ID | Rule | Status | Where | Legacy |
|---|---|---|---|---|
| PF-DOM-26 | A species name is matched as a whole name or alias - never as a substring - and the resolver that does it is the one rule the 2D renderer and the 3D plant builder share. | standing | [09](../09-domain-solver.md#pf-dom-26) |  |
| PF-DOM-01 | No free solver variables does not imply feasibility, so the Newton solver evaluates the pinned-state residual before returning and a convergence flag agrees with measured geometry. | pointer | [09](../09-domain-solver.md#pf-dom-01) |  |
| PF-DOM-02 | A constraint graph row can hide a no-op geometry path, so Edge Length resizes through canonical `geometry_apply` in one undo step, refuses atomically on conflict or pinned-item movement, and tests assert the real relation. | standing | [09](../09-domain-solver.md#pf-dom-02) |  |
| PF-DOM-03 | `search()` and `get_by_id()` return different field sets, so a confirmed search selection fetches the detail record once and merges it field by field, a default or `None` detail field keeping the search value. | standing | [09](../09-domain-solver.md#pf-dom-03) |  |
| PF-DOM-04 | Validate a plant-API detail record by `source_id` alone, merge it field by field treating a present `None` as empty, and stop any pending debounce timer before a commit path opens a modal. | standing | [09](../09-domain-solver.md#pf-dom-04) |  |
| PF-DOM-05 | Before asserting a plant API's response shape, id space, error-code meaning or sweep completeness, settle it with a live call using the working `.env` credentials. | standing | [09](../09-domain-solver.md#pf-dom-05) |  |
| PF-DOM-06 | Every plant search-result row shows its data source through the shared `plant_source_label()`, because a stale custom-library record on a real machine can mimic a live result that mocked tests never see. | standing | [09](../09-domain-solver.md#pf-dom-06) |  |
| PF-DOM-07 | Write every external-API JSON lookup as `(data.get(key) or default)`, since `dict.get(key, default)` returns `None` for a present JSON null, whose chained method call raises and silently drops the record. | standing | [09](../09-domain-solver.md#pf-dom-07) |  |
| PF-DOM-08 | Verify each plant-API field mapping against a live or captured real response rather than a hand-written fixture that encodes the parser's assumption, and map a single-number Soil pH to no range. | standing | [09](../09-domain-solver.md#pf-dom-08) |  |
| PF-DOM-09 | Task status has one write path, `set_task_status`, with `task_completions` kept only as a write-only serialized mirror, and every reader derives `task_id` via `make_calendar_task_id()` and `species_key()`. | standing | [09](../09-domain-solver.md#pf-dom-09) |  |
| PF-DOM-10 | Assign a species through `PlantDatabasePanel._apply_species_to_item()` and its undoable `ApplySpeciesCommand`, since a raw `metadata["plant_species"]` write never repaints, but keep per-keystroke edits out of that command. | standing | [09](../09-domain-solver.md#pf-dom-10) |  |
| PF-DOM-11 | `_compute_constraint_solve_moves()` adds `anchor_c.item_id` to `constrained_ids` for three-anchor constraints such as ANGLE, or the solver cannot move the third item and it stays violated. | standing | [09](../09-domain-solver.md#pf-dom-11) |  |
| PF-DOM-12 | `ConstraintGraph.project_to_feasible()` keeps a sub-pixel default tolerance of `1e-4`, because a cm-scale tolerance makes `newton_refine()` return the cursor unchanged and the dragged vertex slips. | standing | [09](../09-domain-solver.md#pf-dom-12) |  |
| PF-DOM-13 | `ShoppingListItem.id` encodes the locale-stable display unit, as in `amendment:<aid>:g` or `amendment:<aid>:kg`, so a price keyed by id never re-binds after a g-to-kg promotion. | standing | [09](../09-domain-solver.md#pf-dom-13) |  |
| PF-DOM-14 | Surfaces that share the task status store build the whole task id through the shared `make_calendar_task_id()` and canonical `species_key()`, and sync tests derive ids the way production does. | standing | [09](../09-domain-solver.md#pf-dom-14) |  |
| PF-DOM-15 | A handler fed a canonical `species_key` compares `species_key()` on both sides, selects a `target:<uuid>` key by item id, and never shows that grouping key as a user-facing name. | standing | [09](../09-domain-solver.md#pf-dom-15) |  |
| PF-DOM-16 | Every writer of a HOUSE polygon recomputes its roof ridge through `compute_roof_ridge_endpoints` in the polygon's local frame, never re-projecting the ridge from its own current endpoints. | standing | [09](../09-domain-solver.md#pf-dom-16) |  |
| PF-DOM-17 | Assign roof-texture halves by the physical down-slope direction, never by `_split_path_by_line`'s left and right naming, which follows the ridge direction rather than gravity. | standing | [09](../09-domain-solver.md#pf-dom-17) |  |
| PF-DOM-18 | `species_key()` is a module-level function over a species dict, not a record field, so `getattr(record, "species_key", "")` yields an empty key; a bundled plant's key is its scientific name. | standing | [09](../09-domain-solver.md#pf-dom-18) |  |
| PF-DOM-19 | The Tasks tab and dashboard list reminder tasks through `generate_actionable_for_surface` while the Gantt consumes `generate_for_date_window`, so neither the GUI nor the agent hides a task the other shows. | pointer | [09](../09-domain-solver.md#pf-dom-19) |  |
| PF-DOM-20 | Establish which reading the code implements before editing data that contradicts its documentation; harvest offsets count from the last spring frost, and divergent rows stay named in `KNOWN_DIVERGENT_SPECIES`. | standing | [09](../09-domain-solver.md#pf-dom-20) |  |
| PF-DOM-21 | A wrapper over `generate_for_date_window` passes `actionable_only=False` inward and filters urgency once at the edge, because the flag is re-applied inside every anchor year. | standing | [09](../09-domain-solver.md#pf-dom-21) |  |
| PF-DOM-22 | Store the user's chosen local calendar day and derive the UTC instant from it, never the reverse, so UI writers hand `SimClock` a naive wall reading rather than an instant. | standing | [09](../09-domain-solver.md#pf-dom-22) | 11.4.7 |
| PF-DOM-23 | Guild placement deep-copies copied metadata, couples UUID resolution to document lifetime, and takes plant geometry from `guild_plant_bounds()`, since a semantic plant may be a rectangle, polygon or path. | standing | [09](../09-domain-solver.md#pf-dom-23) | 11.4.8 |
| PF-DOM-24 | A plant's soil-plane sun estimate excludes its own caster and applicable soil holders; document replacement cancels heatmap work and rejects late results. | standing | [09](../09-domain-solver.md#pf-dom-24) | 11.4.6 |
| PF-DOM-25 | Project plant presence and rendered growth from the one plan date, preserving stored lifetime metadata and undo semantics. | standing | [09](../09-domain-solver.md#pf-dom-25) |  |
| PF-DOM-27 | A species assignment writes the item's own species string, because that string - not the record's data - is what the sprite resolver reads. | standing | [09](../09-domain-solver.md#pf-dom-27) |  |
| PF-DOM-28 | One caster's footprints are ONE region: a ring whose enclosed area is negative is a hole and must be bridged before the sweep, and a ring that crosses itself must be split into its lobes. Sweep simple rings only. | standing | [09](../09-domain-solver.md#pf-dom-28) |  |
| PF-DOM-29 | Sun exposure of elevated plants must evaluate shadows on the plant's elevated plane ($z = \text{elevation}$), slicing taller obstacles and ignoring obstacles below the receiver elevation. | standing | [09](../09-domain-solver.md#pf-dom-29) |  |
| PF-DOM-30 | A gesture that changes an item's anchor positions (rotation) must run the live solver during the gesture and record every partner correction in the SAME command as the gesture's own change. "Skip the solver while rotating" is a decision, not an optimisation — it leaves a violated relation that the next unrelated move hides. | standing | [09](../09-domain-solver.md#pf-dom-30) |  |
| PF-DOM-31 | A `FIXED` constraint is data, not derived state: round-trip `target_x`/`target_y`, repair a legacy record from the loaded item's own frame, treat a target-less `FIXED` as immobile, and take `ItemIsMovable` away for the duration of a drag instead of resetting the item afterwards. | standing | [09](../09-domain-solver.md#pf-dom-31) |  |
| PF-DOM-32 | Incidence has one residual and one anchor resolver: `incidence_error()` is the single definition shared by the solver, the conflict scan and the Constraints panel, and `resolve_anchor_point()` is the single lookup. A polygon/polyline edge reference is identified by its index, because its `EDGE_*` type is re-derived from the current dominant axis. | standing | [09](../09-domain-solver.md#pf-dom-32) |  |
