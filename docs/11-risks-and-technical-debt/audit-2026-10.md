# Repository Audit 2026-10

Snapshot of Open Garden Planner at `master` @ `84ead2e` (v1.29.0), measured 2026-10-03/04 in a
Linux cloud session (4 vCPU, Python 3.11.15, Qt offscreen). The living register is §11.3 of this
chapter's README; this file is the dated snapshot that produced its `TD-009…` rows (ADR-047).
Machine-readable numbers: `audit-2026-10-metrics.json` (re-run with `scripts/audit_metrics.py`).

## 1. Executive summary

- **Scale and result.** 106 k lines of source, 81 k lines of tests, 407 commits, ten dimensions.
  103 raw findings merged into a ranked ledger of 90 (2 P0, 14 P1, 49 P2, 25 P3), plus 4
  deliberate decisions challenged (§6) and 4 accepted. The 2 P0 and 14 P1 are filed as 14 issues
  (two pairs share one remediation) under epic #392; P2/P3 are its checklist.
- **Verification.** 28 ledger items, every P0/P1 among them, went to independent verifiers who
  tried to refute them by re-running the commands: 22 confirmed, 3 downgraded, 1 upgraded,
  1 reclassified as a deliberate decision, and 1 headline refuted with a narrower residual kept (§9.2).
- **Data loss on save (P0, #394).** Free-text annotations (`TextItem`, on the always-visible
  toolbar) are never serialized by `ProjectManager`; the status bar says "Saved" and a reopen
  yields 0 text items. 1 093 serializer mutants survive the project unit tests, which is how this
  stayed invisible. Copy/paste uses a second serializer that drops 4 fields and 7 item types (#400).
- **Untranslated German output (P0, #393).** 5 duplicate keys in `scripts/fill_translations.py`
  silently shadow 62 translations; 5 strings on the opt-in "Garden journal notes" PDF page ship in
  English. The test that guards `de.ts` cannot see a key that never reaches the table.
- **Load-path integrity (P1, #397, #403).** The loader drops undecodable items without a warning,
  including a legacy background image whose file moved (lost permanently on the next save); a
  `.ogp` that fails mid-load leaves the previous file as save target, so Ctrl+S overwrites the
  user's good plan.
- **Gates that exist only as prose (P1, #399, #401, #402, #404, #405).** mypy (2 104 strict errors
  in 134 of 248 files), coverage (80.2 % non-UI lines / 66.4 % branches against a written 80 %),
  the formatter (427 of 577 files differ) and handled-error logging (0 handlers, 55 call sites) are
  declared in the docs and enforced nowhere. Required status checks on `master` are off; PR #323
  merged on a red Test. The release build has no lockfile (4 of 42 runtime dists exact-pinned).
- **Agent API (P1, #396).** The loopback MCP endpoint's only browser barrier is an mcp SDK default:
  mcp 1.22.0, allowed by the `>=1.12` floor, served 6 of 6 hostile `Host`/`Origin` requests. Every
  measured release bundled 1.30.0 (served 0), so no shipped exe is known to be exposed.
- **Tests.** 6 735 tests pass in three randomized orders (no order dependence). The weak spots are
  coverage holes in hotspots: `constraint_tool.py` 29.0 % lines / 9.6 % branches (#406), the four
  array tools 1.2-1.3 % (#395). Mutation scores of twelve core modules range
  15.8-87.9 % killed, each run against a selected unit-test subset (§9.3).
- **Performance and agent context (amber).** Offscreen, a 500-object plan repaints at fit-in-view in
  77.7-80.1 ms/frame, 63 % of it in Qt's raster code; the real-window check is handed to Windows
  (§8). `CLAUDE.md` is 52 % shipped-story narrative; it was 830 B under the Codex cap before this PR
  trimmed 789 B. §7 is the restructuring plan.
- **What changed in the docs.** §11.3 is now the living debt register (status and issue columns,
  TD-001…TD-033, ADR-047); stale §11.1/§11.2 rows carry a status; §10.6 states what CI actually
  enforces. `scripts/audit_metrics.py` re-creates every number in `audit-2026-10-metrics.json`.

## 2. Scope and method

**Scope.** Everything under `src/`, `tests/`, `scripts/`, `docs/`, `.github/`, `.claude/` and
`.agents/`; ten dimensions: architecture and layering, hotspots and complexity, test-suite
quality, quality gates and CI, security and trust boundaries, dependencies and reproducibility,
performance requirements, documentation and knowledge architecture, agent-context engineering,
process and release. Out of scope: product behaviour beyond what the measurements touch, and
anything that needs a Windows machine (listed in §8).

**Evidence bar.** Every finding carries the instrument, the exact command, a verbatim output
excerpt and `path:line` at `84ead2e`. Findings were classified against the project's own
knowledge (ADRs, architecture weak points, failure archaeology, §11.1–§11.4) before being
ranked: `new`, `known-open`, `known-stale`, or a deliberate decision (which is listed in §6, not
ranked). Every Top-25 candidate was then handed to an independent verifier (three `senior-reviewer`
runs, 28 items in total, because downgrades and one reclassification moved three P2 items into the
Top-25) that tried to refute it by re-running the command and re-reading the lines; verdicts are in
the ledger column, refutations in §9.2. Items outside the Top-25 were not re-verified and say so.

**Instruments and versions.** pytest 9.1.1 (+ pytest-qt 4.5.0, pytest-timeout 2.4.0,
pytest-randomly 5.0.0), coverage 7.16.2 (branch), mypy 2.4.0 (project `pyproject.toml` strict
config), ruff 0.16.10, bandit 1.9.4, pip-audit, radon 6.0.1, mutmut 3.8.0, import-linter 2.15 /
grimp 3.17, git 2.x over the full 407-commit history; mcp 1.30.0, PyQt6 6.11.0 installed.

**Reproduction.** All commands were run from the repository root at `84ead2e` inside the project's dev
venv (`pip install -e ".[dev]"` plus `mutmut`, `pytest-randomly`, `import-linter`, `grimp`, `radon`,
`pip-audit`), with `QT_QPA_PLATFORM=offscreen` and `PYTHONUTF8=1`.

## 7. Agent-context restructuring plan (analysis only; implementation is a separate package)

**Baseline (measured 2026-10-03).** Every session starts with `CLAUDE.md` (31 938 B, about 8.0 k
tokens, 52 % of it shipped-story narrative) plus 21 skill descriptions (13 693 B, about 3.4 k tokens):
roughly 11.5 k tokens before the first prompt. Loading `debug-verbose` adds about 36 k tokens (144 540 B,
47 case studies, +76 874 B in 55 days). `CLAUDE.md` sits 830 B under the Codex budget of 32 768 B
(`.codex/config.toml`) after growing 12 767 B in eight days; the next shipped-package bullet in the
current style would have failed the `agent-context` CI job. This PR trims 789 B (one narrative bullet
replaced by a pointer plus the audit line), leaving 1 619 B: a reprieve, not a fix. The repository has no hooks, no permissions file and no
path-scoped rules; 13 MUST/NEVER rules in `CLAUDE.md` have no machine check (6 have none at all). The
20 byte-level differences between `.claude/skills` and `.agents/skills` are all product-name
normalisation; the parity gate holds.

**Target state.**

1. Root `CLAUDE.md` of at most 200 lines / 12 KB: Quick Reference, the MUST/NEVER rules, the two
   mandatory-update tables, and a ten-line "where to pick up" that points at `docs/roadmap.md`
   "Current state", the last three PR numbers and `git log`, instead of narrating.
2. The progress narrative moves to the docs of record: a `## Current state` section at the top of
   `docs/roadmap.md`, the per-story lessons into the ADR addenda and §11.4 entries that already hold
   about 77 % of them. Three facts exist only in `CLAUDE.md` today (the 64/64 bearer casings, the
   21-of-26 roof-ridge cases, the preview-z band 999–1002) and land in §11.4 / ADR-046 / §8.25.6 first.
3. Path-scoped rules as nested `CLAUDE.md`/`AGENTS.md` pairs (both hosts load nested root docs;
   `.claude/rules/` is Claude-only) for `src/open_garden_planner/ui/`, `src/open_garden_planner/agent_api/`
   and `tests/`, each at most 3 KB; the parity gate learns to compare every pair it finds.
4. `debug-verbose` becomes a method (about 5 KB) plus a one-line-per-case index with symptom keywords
   and `cases/<date>-<issue>-<slug>.md`; an agent opens the two or three matching cases.
5. The five other skills above 30 KB move tables and appendices into `references/*.md` inside the skill
   directory (progressive disclosure), keeping each `SKILL.md` body at or under 20 KB.
6. Every skill description at most 500 B, imperative trigger first, one discriminating cue against its
   nearest neighbour; two stale descriptions fixed.
7. Hooks (candidates in the audit measurements, `hook_candidates.md`): blocking for master commits,

   fix touches `src/`.
8. A committed `.claude/settings.json` permissions allowlist for the read-only git, pytest, ruff and
   `scripts/check_*` commands agents run every session.
9. A size budget in `scripts/check_agent_context.py` (warn above 16 KB, fail above 24 KB) so growth is
   caught long before the 32 768 B cap.

**Migration order** (each a chore PR): (1) land the three unique facts and the roadmap "Current state",

This contract was run during D01 with import-linter 2.15. It was not committed.

Result over `src/`: 248 files, 835 dependencies, 0 kept, 2 broken. The verdict does not model the
project's rule: grimp records function-local imports as ordinary edges, while invariant 11 allows a
function-local `core → ui` import as the cycle breaker. The first contract fails on 171
function-local imports, of which only 6 statements are real violations; the second fails on 6
transitive chains, each through a function-local import in `services` or `core` (e.g.
`agent_api.render` → `services.export_service` → `ui.canvas.items.construction_item`); `agent_api`
has 0 direct runtime `ui` imports (`exports.py:37` is `TYPE_CHECKING`). The contract is therefore
usable only with the module-level/function-local split of the audit's AST pass (`layering_ast.py`;
`scripts/audit_metrics.py` carries the same rule). Proposed split (AUD-003, AUD-005, AUD-008):

1. **Module-level rule as an AST test** in `tests/unit/test_layering.py`. Module-level `ui`/`app`
   imports from `core`, `services`, `models` and `agent_api` must equal an allow-list that may only
   shrink. Today's six entries:

2. **import-linter only for contracts that hold with function-local edges.** `models → ui/app` has 0
   chains and can be enabled now (AUD-005). An `agent_api → ui` contract restricted to direct
