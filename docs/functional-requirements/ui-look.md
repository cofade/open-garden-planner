# User interface and look

## User interface

- **FR-UI-01**: Modern, flat design consistent with Windows 11 aesthetics
- **FR-UI-02**: Branded green theme with light/dark variants. Every chrome surface — painted charts and the canvas rulers included — follows the app's theme, whatever the operating system's mode (#791, ADR-039 addendum).
- **FR-UI-03**: Fixed sidebar panels (not dockable/floating)
- **FR-UI-04**: Keyboard shortcuts for all common operations
- **FR-UI-05**: Context menus (right-click) for relevant actions
- **FR-UI-06**: Tooltips on all toolbar buttons
- **FR-UI-07**: Status bar: cursor coordinates, zoom %, selection count, current tool
- **FR-UI-08**: Welcome screen with recent files
- **FR-UI-09**: Remember window size, position, panel states between sessions
- **FR-UI-10**: The category toolbar opens visual thumbnail galleries for browsing and placing objects and plants.
- **FR-UI-11**: Fullscreen preview mode (F11) hiding all UI overlays
- **FR-UI-12**: Toggleable object labels on canvas
- **FR-UI-13** *(issue #304)*: Across the main toolbar and the constraint toolbar **exactly one tool button is highlighted at any time — the active tool's**. The two toolbars own separate exclusive `QButtonGroup`s, so the app reconciles them itself: `ToolManager` emits `tool_type_changed(ToolType)` alongside the display-name `tool_changed(str)`; `GardenPlannerApp` forwards it to both toolbars' `set_active_tool()`, each of which unchecks its own group when the active tool is not one of its buttons. (Before this, the sync was a hard-coded map from tool *display name* to `ToolType` that knew only three of the ~15 constraint tools — every other tool, e.g. **Equal Size**, never reached the toolbars at all, so **Select** stayed highlighted too and the user could only reach objects via right-click; keying on display names — several of which are translated at import — was a second fragility the type-keyed signal removes.) Pinned by `tests/integration/test_toolbar_highlight_sync.py` (which drives every constraint-toolbar tool plus the main-toolbar tools through the real window).
- **FR-UI-14** *(issue #569, updated by #986)*: Preferences keeps every control at its natural height on a short screen. Each tab's settings form (`FR-UI-PREF-01`) lives in its own scroll area with Save / Cancel outside every viewport, so Tab reveals the last setting instead of a control squeezed to zero height; the dialog opens wide enough to display all five tabs without horizontal scroll arrows and tall enough for the tallest tab, both capped to the available screen. Pinned by `tests/integration/test_preferences_layout.py` at 400 and 800 px, 10 and 14 pt, in both themes.
- **FR-UI-20**: Keyboard navigation for all functions (Deferred / partial; see ACCESSIBILITY.md for current keyboard shortcut coverage and navigation boundaries)
- **FR-UI-21**: High contrast mode support (Deferred / platform-inherited; see ACCESSIBILITY.md)
- **FR-UI-22**: Configurable font sizes in UI (Deferred; see ACCESSIBILITY.md)
- **FR-UI-23**: Category-based thumbnail gallery (Trees, Shrubs, Flowers, Furniture, etc.)
- **FR-UI-24**: Each item: illustration thumbnail (~64-80px) + name label
- **FR-UI-25**: Click thumbnail to enter placement mode
- **FR-UI-26**: Drag from thumbnail to canvas for direct placement
- **FR-UI-27**: Category popups fit the screen work area and scroll their results. Name
  and plant trait filters pack matches at the top and clear on reopening.
- **FR-UI-28**: Flowers & Perennials offers separate localized entries for *Tagetes erecta*,
  *Calendula officinalis* and *Pelargonium × hortorum* (#950).

## Theme, icons and Preferences

- **FR-UI-THEME-01**: Chrome follows the selected theme **everywhere**: semantic status colors (error/warning/success/info/caution and their tinted `*_bg` surfaces) come from the palette in every panel, dialog, view, banner and overlay — including the previously theme-blind weather forecast cards, the task-reminder and update banners, and the companion-check score colors — and a **live theme switch restyles the running app** without restart (icons re-tint, palette-driven views re-render).
- **FR-UI-THEME-02**: Typography is role-based (h1/h2/hint/small/placeholder plus semantic color roles) and styled centrally; dialog CTAs use accent-branded primary/secondary button roles.
- **FR-UI-THEME-03**: Widget code may not hardcode chrome colors — `ui/theme.py` is the single home of chrome hex values, enforced by a repo lint gate.
- **FR-UI-ICON-01**: Every chrome icon — drawing/constraint toolbar tools, gallery category chips, and the common menu actions (File/Edit/View/Help; extended to every menu, the status bar, the dashboard tabs and all panel-level pseudo-icons by FR-ICON-3C, #310) — is a line icon rendered through the central provider from `resources/icons/ui/`, tinted from the **active theme** at runtime: cohesive on light AND dark, with a muted per-category identity tint on the gallery chips and a fully grayed Disabled state (e.g. the constraint toolbar's coming-soon buttons). An unknown/missing icon degrades to the pre-existing text fallback, never a broken image.
- **FR-UI-ICON-02**: Every shipped icon passes the mechanical conformance gate (24×24 square, `currentColor` + accent-sentinel colors only, no rendered text, no rasters) and carries a provenance entry with a GPL-3-compatible license basis — no entry, no merge.
- **FR-UI-PREF-01** (#986): Preferences is a tabbed dialog, not one long form: **General** (units, canvas, tasks), **Weather**, **Online services**, **Agent API** and **3D View**. Each tab scrolls on its own; Save and Cancel stay outside every viewport and are always reachable. Every existing preference keeps its current key and default.

Acceptance: `tests/integration/test_icon_system.py` + `tests/integration/test_theme_switch_chrome.py` (§8.10) plus the `test_icon_conformance` / `test_no_hardcoded_qss_colors` / `test_theme_tokens` gates.

## Sidebar accordion

- **FR-UI-SIDEBAR-01**: Every sidebar panel starts **collapsed** (header-only bar) on each launch; no panel/pin state is persisted across sessions.
- **FR-UI-SIDEBAR-02**: **Hovering** a collapsed bar peeks it open in place after a short debounce (pushing bars below it down); leaving collapses it again after a longer debounce. Fast pointer sweeps do not flicker the bars (re-entering a bar cancels its pending close).
- **FR-UI-SIDEBAR-03**: **Clicking** a panel title toggles it open/closed. Open and close are **animated** (an organic height expansion, not a hard switch). Panels keep a **fixed order** — opening or closing one never reorders the list.
- **FR-UI-SIDEBAR-04**: Open panels **fill the available space** rather than leaving an empty gap: a single open panel expands to fill the sidebar; when several are open each keeps at least its content height and the surplus is shared weighted by content size; when their combined content exceeds the sidebar height it **scrolls**. (There is no draggable divider.)
- **FR-UI-SIDEBAR-05**: The three selection-driven panels (Plant Details, Companion Planting, Crop Rotation) are **hidden entirely** unless a matching item is selected — they do not linger as empty placeholder bars. Selecting a single plant **shows + auto-opens** Plant Details and Companion Planting; selecting a single bed shows + auto-opens Crop Rotation; selecting anything else (or nothing) hides all three. The user can **close a shown panel with a single click**, and it stays closed for that selection; a different selection re-opens it. These three panels are gated purely by relevance — even one the user manually opened is hidden when it becomes irrelevant. (A non-contextual panel the user opens manually, e.g. Layers, stays open across selection changes — see FR-UI-SIDEBAR-03.)
- **FR-UI-SIDEBAR-06**: Peek and pin are visually distinct (peek = accent border; pin = left accent rail), with an instant hover highlight on collapsed bars. Keyboard equivalents are deferred (v1 is mouse-only).

## Iconography and the View menu

- **FR-ICON-3C-01**: Every remaining chrome surface carries a themed provider icon (`ui/icons.py`, ADR-039 contract): the status bar (a small glyph in front of every segment — coordinates, typed coordinate input, zoom, selection, tool, location, season, the transient sun hint), the five dashboard tabs, the frost corner badge, every File / Edit / View / Plants / Garden / Help menu action including submenu titles and per-format Export glyphs (PNG / SVG / CSV / PDF / DXF) — the only plain entries are the exclusive-choice radios (Theme, Language, Auto-Save intervals) and the dynamic recent-files list. All of them re-tint on a live theme switch.
- **FR-ICON-3C-02**: The View menu is grouped: Zoom (top level) · **Snapping ▸** (grid, snap-to-grid, objects, midpoints, intersections, nearest, perpendicular, tangent, dynamic input) · **Overlays ▸** (scale bar, labels, constraints, construction geometry, guide lines, companion warnings, spacing circles, soil health, minimap, previous-season) · **3D View** (direct workspace action) · Fullscreen Preview · Theme ▸ · Language ▸ — every toggle iconized; keyboard shortcuts unchanged.
- **FR-ICON-3C-03**: Dashboard tab shortcuts are contiguous: Ctrl+1 Garden Plan, Ctrl+2 Planting Calendar, Ctrl+3 Seed Inventory, **Ctrl+4 Tasks**, **Ctrl+5 Harvest** (were Ctrl+5 / Ctrl+6; Ctrl+4 had been vacant since the Paper-Space tab was dropped).
- **FR-ICON-3C-04**: No emoji or unicode pseudo-icon remains in chrome: seed viability (✓ ✗) → status icons in the Viability column; task/calendar urgency dots (●) → painted themed markers; go-to arrows (→) → arrow icons; plant-search type glyphs (🌳🌿🌸🌱, also inside translated checkbox labels) → the gallery's tree/shrub/flower/seedling icons; weather refresh/expand (🔄 ▾ ▴) and the WMO condition emoji map → refresh/chevron icons and sun/partly-cloudy/fog/rain/snow/storm icons; journal photo marker (📷) → camera icon; companion "nearby" star (★) → star icon; the panel info glyph (ℹ️) and accordion chevrons (▼ ▶) → provider icons; the constraints panel's type glyphs (◯ 🔒 ↔ ↕ ⦿ ⌒ ≡ ∥ ⊾ ∠, in labels and tooltips) → the constraint toolbar's own type icons and plain words, its "×" delete button → the cross icon; the calendar's propagation "↳" sub-row marker and "↺" reset buttons → chevron/refresh icons; the succession dialog's ✓/⚠/· note prefixes → a list with status icons; the crop-rotation panel's ✅ ⚠ ❌ ❓ status prefix → a tinted status icon; the tri-state frost tooltip's ☑ ☐ ‒ → words; the 3D window's text-only Refresh/Walk toolbar → icons; the fixed-constraint canvas preview label drops its 🔒; the season manager's ✓ ✗ ▶ → status icons + bold; the canvas fixed-padlock badge keeps its painted body/shackle and drops the trailing 🔒 text; the theme's spin-box arrows are path SVGs instead of `<text>` glyphs. Textual arrows inside sentences ("File → Set Location", "A → B: reason", "pH 5.8 → 6.5"), canvas text (dimension-label prefixes "↔ 1.20 m", the constraint tools' on-canvas preview labels "≡ H (same Y)" / "⊙ On Circle" — drawn in the app font on the canvas, not chrome), the update banner's external-link arrow ("What's new ↗", typography) and combo separator rows are prose and stay (§8.21.5 lists them; the static guard scans every string constant of the migrated modules and names its exceptions).
- **FR-ICON-3C-05**: The layers panel's eye/lock buttons come from the provider (tinted accent / secondary / warning, re-tinted on theme switch) — the last private `QSvgRenderer` chrome path is gone; the sun-simulation toolbar shows play/pause, a sun-hours glyph and a clock; the soil-overlay toolbar shows its glyph; the properties panel's long-missing `lawn` icon exists.
- **FR-ICON-3C-06**: A code→file gate (`tests/unit/test_icon_names_referenced_in_src.py`) fails when code requests an icon name that has no file (the class of drift that hid the missing `lawn.svg`); the icon set (150 Tabler + 12 bespoke) stays fully conformant and provenanced.

## Visual rendering

- **FR-VIS-01**: Tileable PNG textures for materials (grass, wood, stone, water, etc.)
- **FR-VIS-02**: Illustrated SVG plant shapes (category-based + unique popular species)
- **FR-VIS-03**: Subtle drop shadows on all objects, always enabled
- **FR-VIS-04**: Visual scale bar overlay on canvas. Its label is readable on every background and never covered by the minimap *(issue #793)*.
- **FR-VIS-05**: Object labels (plant names, custom text) toggleable per-object and globally
- **FR-VIS-06** *(issue #793)*: Every label on the canvas (object name, area, dimension and constraint text, scale bar) is drawn over a halo and shows a contrast of at least **4.5:1** (WCAG AA) between its text and what surrounds the text, on any background. A dimension's text is a darker shade of its line's colour where the line colour alone would not reach that. An object's label is centred on the object at every zoom and is drawn above all objects. Labels never overlap: when the plan is zoomed out, an object smaller than 14 px on screen shows no label, and of two labels that would touch the larger object's is shown; the selected object always shows its label. An export shows the labels the canvas shows. Dimension text participates in that same placement. Owner label stacks move together inside the plan edge; spacing arcs leave edit handles and annotations clear. Minimap thumbnails omit diagnostics without changing live visibility (#843).
- **FR-VIS-07** *(issue #793)*: A text note keeps its letter spacing at every zoom. Its **Size** in the Properties panel is the height of its font on the plan in centimetres (the default note is 37 cm; capital letters are about 70 % of that); a plan file's stored text sizes are unchanged and draw as before *(issue #836)*. Stored whole-point sizes resolve at a fixed 96 dpi into plan-scaled pixels, so another screen DPI does not change a note's plan size. The historical 96 dpi appearance is retained. Native Windows pixel tests, including a full-hinting negative control, pin letter spacing (#872, #874).
- **FR-VIS-08** *(issue #786)*: With **View > Overlays > Show Spacing Circles** on (the default), a plant that is too close to a neighbour is marked by a thin dashed warning line drawn only where its spacing circle overlaps that neighbour's; nothing is filled. The selected plant shows its whole spacing circle; a plant whose spacing is fine and that is not selected shows none. Two plants are compared only within one storey: a tree is never reported against what grows under its crown (ADR-028 addendum). The Diagnostics panel lists the same warnings.
- **FR-VIS-09** *(issue #786)*: Exported pictures of the plan (PNG, SVG, PDF report, print, the Agent API's `render_canvas_image`) show no diagnostic overlay: no spacing circle, companion ring, antagonist, capacity, sun-mismatch or guild badge, and no soil or crop-rotation border. Diagnostics remain available through the Diagnostics panel and `get_diagnostics`. A bed's succession badge is not a diagnostic: it is in every picture. On the canvas it is drawn above the plants of its bed and only where it lies inside the bed and covers at most a quarter of it *(issue #836)*. An upright succession tag is contained by the actual transformed bed outline and reserves room against other labels. Where text has no room, a compact crop-following arrow remains; below 3 screen pixels no readable indicator fits (#844).

## Plant illustrations

- **FR-PLANT-ART-01**: Every species (111) and category (15) plant sprite renders in one cohesive top-down "Lush Sprite" style — individual shingled leaves with depth (occlusion + per-leaf gradients), glossy fruit and chunky bloom clusters — replacing the washed-out translucent-blob set, on the same files and render path the canvas already uses (no behavior change in `plant_renderer`).
- **FR-PLANT-ART-02**: Sprites stay visually correct under the canvas' stable per-plant random rotation (radial shading, no baked light direction) and remain legible at small growth-model sizes (≈16 px) as well as large tree footprints.
- **FR-PLANT-ART-03**: Each species keeps one signature recognition cue at plan scale (fruit color, bloom shape/color, rib color, root-vegetable bulb at the center, silhouette — e.g. tomato ≠ pepper ≠ eggplant, carrot ≠ radish ≠ beet).
- **FR-PLANT-ART-04**: The whole set is procedurally regenerable by `scripts/generate_plant_sprites.py` from per-species recipes — since Phase 17 L1.7 the recipe tables live in `core/plant_art/recipes.py`, shared with the 3D plant builder (FR-3D-PLANT-01); committed SVGs byte-match regeneration (deterministic, seeded) and carry provenance (`resources/plants/PROVENANCE.md`) — no external or image-model assets.
- **FR-PLANT-ART-05** *(issue #446)*: A species name is matched as a **whole name or alias**, never as a substring, and one resolver answers for both views. The name is matched in three steps: the whole name; else a key whose every word is a word of the name ("Broad Bean" -> bean, "Winter Squash" -> squash); else a key that holds every word of the name ("Solanum" -> tomato). A name no sprite knows falls back to the plant's **category** sprite. The second step's tie-breaks are: the key with the most words, then the longest key, then the table's order (the length is a real tie-break - two one-word keys inside one name, "lavender rose", are both one word, and the longer key wins). Whole-name-only was measured and rejected: it changes 266 of the 1,562 pinned answers over 110 distinct names, and most of those are regressions - "Quercus robur", "Broad Bean", "Sweet Corn" have no exact key and would fall back to a generic sprite. The rule that shipped changes 74 answers over 37 names, and of the bundled species' 118 names exactly one changes - the melon, which was drawn as an eggplant. **What it does not fix:** "Lemon Balm", "Bean (Bush)" and "Sweet Potato" still take a fruit or vegetable sprite, because their names contain a whole word that is another plant's name; a curated alias table would be needed, and was declined.

Acceptance: `tests/unit/test_plant_sprite_conformance.py` (coverage, QtSvg-subset contract, determinism/no-drift) + `tests/integration/test_plant_sprite_rendering.py` (§8.10 — every sprite renders visible pixels through `render_plant_pixmap`, incl. tint/rotation/16 px).

## Object sprites

- **FR-OBJ-ART-01**: Every furniture and infrastructure object renders in one cohesive top-down "Lush Object" style at full parity with the plant sprites — per-part rim-dark → crown-light shading, occlusion where parts stack, material micro-detail (wood grain, brushed metal, fabric weave, water ripples, soil/sand grain), gloss on glossy materials — on the same files and render path the canvas already uses (no behavior change in `furniture_renderer`).
- **FR-OBJ-ART-02**: Sprites bake **no directional shadow**; the item-level painted shadow (View › Shadows) is the single shadow source, so objects stay visually correct under user rotation and the shadow toggle behaves identically for furniture and plants.
- **FR-OBJ-ART-03**: The roster grows by nine placeable object types — sandbox, trampoline, hot tub, swing, picnic table, hammock (Furniture gallery) and wheelbarrow, pergola, bird bath (Infrastructure gallery) — each with a tool, gallery thumbnail, translated display name and "Change Type" membership for its shape; the solid ones (sandbox, trampoline, hot tub, picnic table, wheelbarrow, bird bath) carry a default height so they cast shadows and extrude in 3D, while the open structures (swing, pergola, hammock) cast none by default because the shadow model extrudes a solid footprint — their Height field is still offered so a user can opt one in (superseded by FR-3D-BUILT-01: since L4's owner passes they have default heights too). Plans containing them stay loadable by older app versions (unknown types degrade to generic shapes; no file-format bump).
- **FR-OBJ-ART-04**: Gallery thumbnails preserve the object's real aspect ratio (a bench is a long thin board, not a square block); the BBQ/grill — a round-tool object — ships square art and is offered when changing a circle's type.
- **FR-OBJ-ART-05**: The whole set is procedurally regenerable from `scripts/generate_object_sprites.py`; committed SVGs byte-match regeneration (deterministic, seeded), obey the QtSvg-subset allowlist and element/byte budgets, and carry provenance (`resources/objects/PROVENANCE.md`) — no external or image-model assets.

Acceptance: `tests/unit/test_object_sprite_conformance.py` (coverage vs generator + renderer maps, QtSvg subset, budgets, viewBox = default footprint, no baked shadow, determinism) + `tests/integration/test_object_sprite_rendering.py` (§8.10 — every sprite renders through `render_furniture_pixmap` within the visual-weight band, legible at 24 px, letterboxed thumbnails, every new tool draws and paints) + `tests/unit/test_project_unknown_object_type.py` (forward-compat pin).

## Textures

- **FR-TEX-01**: Every fill pattern (all 24 textures — lawn, soil, water, glass, roof tiles, wood, gravel, concrete, hedge and the 15 optional materials) renders in one cohesive top-down "Lush" language — visible material detail, radial rim-dark → crown-light shading per element, occlusion where elements stack — on the same loader, tint and brush path the canvas already uses.
- **FR-TEX-02**: Textures tile **seamlessly on the canvas** at any item size — including the greenhouse's default glass fill and flagstone, whose legacy wrap seams were visible on every plan (gated at 1:1 in both axes on the item's real tinted brush; the view scales that brush, so other zooms inherit it — not separately gated).
- **FR-TEX-03**: The user's fill colour still recolours a textured surface (red bed vs blue bed read as red and blue) without flattening the material detail; a texture that would collapse under tint is rejected by the gate.
- **FR-TEX-04**: Textures bake no directional light, so fills look identical under the view's Y-flip and next to rotated objects.
- **FR-TEX-05**: The whole set is regenerable from `scripts/generate_asset_forge_textures.py`; committed PNGs are pixel-identical to regeneration (deterministic, seeded, `--check`), pass the tileability metric, and carry provenance (`resources/textures/PROVENANCE.md`) — no external, photographic or image-model assets.

Acceptance (FR-TEX-04 — no directional light — is binding but reviewed, not mechanically gated, §8.24): `tests/unit/test_texture_forge_conformance.py` (registry ↔ loader ↔ files, 256² RGB, pixel determinism + rounding-tie margin, roof overhang RNG replay, tint band, gate teeth, legacy generator absent) + `tests/unit/test_texture_tileability.py` (all 24 ≤ 1.6, parametrized — no grandfather list) + `tests/integration/test_texture_forge_rendering.py` (§8.10 — paints with detail through the real panel/brush/item/flipped-render path, no wrap seam on the item's real brush, tint reads, thumbnails, greenhouse tool) + `tests/integration/test_asset_forge_textures.py` (`.ogp` round trip for every pattern).

## Languages

- **FR-I18N-01**: All UI strings translatable via Qt Linguist (tr() calls)
- **FR-I18N-02**: English as default language
- **FR-I18N-03**: German translation shipped at launch
- **FR-I18N-04**: Language selectable via View > Language; restart applies the saved choice
- **FR-I18N-05**: Extensible: contributors can add languages via .ts files
- **FR-I18N-06**: Plant scientific names not translated (Latin)
- **FR-I18N-07**: All registered target languages must completely cover the source-derived UI key set. Both new UI strings and new language registrations require complete catalogs, valid placeholders and matching compiled output before merge. Missing localized companion explanations fall back to English; German explanations are selected only for German (#496).
- **FR-I18N-08**: Spanish localization (`es`, "Español") shipped with 100% key coverage of all source strings, collision-free menu accelerators, valid placeholders, and NSIS installer support.
- **FR-I18N-09**: Russian localization (`ru`, "Русский") shipped with 100% key coverage of all source strings, collision-free menu accelerators, valid placeholders, and NSIS installer support.
- **FR-I18N-10**: Numbers, month names and weekday names in the UI follow the UI language, never the operating system's locale on its own; the system contributes its region only when it speaks the same language (#792, ADR-077).
- **FR-I18N-11**: A number field accepts a comma or a point as the decimal mark in every UI language, typed or pasted (keyboard or context menu), and accepts back what the UI shows; a single mark is never read as a thousands separator, and a free-text number field refuses `nan`, `inf` and exponents; machine-readable files (.ogp, DXF, CSV, clipboard rows) keep a decimal point in every language, while a reader-facing picture (SVG text, PDF report) follows the UI language like the canvas (#792, #860, ADR-077).
- **FR-I18N-12**: The UI language does not choose date and time conventions: every date field shows ISO (`yyyy-MM-dd`), every time field 24 hours, every calendar popup starts on Monday, and a date written in text names its month ("7 Jun 2026"), in every UI language and on every system (#792, ADR-077 decisions 7 to 9).
- **FR-I18N-13**: French localization (`fr`, "Français") shipped with 100% key coverage of all source strings, collision-free menu accelerators, valid placeholders, and NSIS installer support (#553).
