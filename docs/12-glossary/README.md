# 12. Glossary

## 12.1 Terms

| Term | Definition |
|------|-----------|
| **Receiver sun estimate** | Direct sun accumulated at a plant footprint's heatmap cell centre at ground level, excluding only its own solid shadow; 15-minute sampling, no leaf-height or translucent-canopy model (ADR-056). |
| **Sun evaluation** | Cached hours for a runtime document/date/geometry snapshot, or an explicit unavailable reason. An absent mismatch is not evidence of completed evaluation. |
| **Mature-canopy grouping** | Other footprint centres inside/on a selected tree's recorded mature spread circle; independent of guild, bed and drawing layer, without asserting the cause of shade. |
| **arc42** | Template for software architecture documentation (12 sections) |
| **Accent sentinel** | The reserved hex `#3D8B37` inside UI icon SVGs — replaced with the active theme's `accent` at render time by the icon provider (equals the light-theme accent so raw files preview correctly). ADR-039 |
| **Icon provider** | `ui/icons.py` — the single render path for chrome icons. Substitutes theme colors into the SVG text before rasterizing (QSvgRenderer paints raw `currentColor` black), renders at devicePixelRatio, caches per (name, size, tint, accent) |
| **Semantic color token** | A named entry in `ThemeColors.LIGHT/DARK` expressing intent (`error`, `warning_bg`, `caution`, …). Widget code reads it live via `theme_color()`/`rgba()` instead of hardcoding hex — enforced by the QSS-color lint gate |
| **Text role** | The `textRole`/`colorRole` dynamic label properties (h1/h2/hint/small/placeholder; success/…/secondary) styled centrally by the generated stylesheet; assigned via `theme.set_text_role()` |
| **Canvas** | The main drawing area where garden objects are placed and manipulated |
| **Beauty Board** | The fixed set of 3D shots of `tests/fixtures/plans/bench_small.ogp` (golden hour, sunset, noon, morning, December noon, night, walk) per render preset, rendered before and after every 3D-visible change together with its `metrics.json`; judged by the `ogp-3d-reviewer` and the owner. Procedure in the `ogp-lush-cinematic` skill (Phase 17) |
| **Truth gate (3D)** | A measured check that a 3D frame still states the plan's data: mesh height and spread vs the resolved values, shadow-map footprint vs the analytic 2D shadow (IoU), north-up ground, the sky's sun at the solar azimuth, the plan date. A failed truth gate is a P0 however good the frame looks (ADR-048) |
| **Truth principle** | "A beautiful wrong frame is a P0": the 3D view may only show what the plan's data says. Since Phase 17 L1.1 the gates that need no pixels are tests in the Qt-free pipeline — mesh top = resolved height (`verify_builder`), faces lit from their own side (`Mesh.validate`), the 2D footprint (golden fixture), the ground a solid covers (`verify_builder`'s plan view), nothing mirrored (frame determinant +1). See ADR-064 decision 13 |
| **Scene record** | `core/scene3d.Record` — one plan item as plain immutable data for the 3D pipeline: item-local outer rings and their holes, resolved height, params, a rigid transform and the item's material. Everything a builder may read. Produced by `snapshot_records` on the GUI thread; contains no Qt object (§8.32.1) |
| **Item-local frame** | The coordinate frame of a scene record and of its meshes: centimetres about the item's anchor (its centre), z up from the item's own ground. The record's transform places it in the scene, so moving or rotating an item re-poses a Model instead of rebuilding a mesh (ADR-064) |
| **Record grid** | The resolution every scene record is snapped to: 1e-7 cm for lengths, 1e-9° for angles. It makes the same geometry reached along two float paths one record — without it a HOUSE with a ridge was rebuilt on 689 of 1,000 moves — and is too fine to hide an edit (ADR-064 decision 5) |
| **Signature (scene record)** | One of three hashes on a scene record — geometry, transform, material — that say which aspect of an item changed between two snapshots. An accelerator only: equality is confirmed on the values, because Python hashes collide on real edits. The item's id, name and parent link are in none; selection and hover are not in the record |
| **Scene diff** | `core/scene3d.SceneDiff` — the difference of two snapshots as item ids: `added`, `removed`, `transform`, `material`, `geometry` (three independent comparisons per surviving item) and `reordered` (paint order changed; no engine call) |
| **Builder (3D)** | A pure function from one scene record's geometry part to mesh parts in the item-local frame, registered per ObjectType name in a `BuilderRegistry`. It may not read the transform, the material or the item's identity; `verify_builder` enforces that. Kinds without one get the default prism builder |
| **Mesh part** | `core/scene3d.MeshPart` — one mesh of an item plus how the engine shows it: a material kind, whether it casts a shadow, and whether the sink tints it with the item's colour (so a recolour never rebuilds a mesh) |
| **Engine sink** | `core/scene3d.EngineSink` — the ten-method boundary through which the 3D pipeline tells a renderer what changed (`add`, `remove`, `update_transform`, `update_material`, `replace_geometry`, `set_sun`, `set_ground`, inside `begin`/`commit`) plus `clear` — hold nothing, legal at any time — the verb recovery needs. Qt Quick 3D implements it in L1.2 |
| **Outer ring / hole (scene record)** | The two kinds of ring in a scene record. `footprints` holds outer rings — simple polygons, counter-clockwise; `holes[i]` holds the clockwise rings cut out of `footprints[i]`. The ground an item covers is the outers minus the holes (`Record.regions`, `Record.plan_area_cm2`). A fence that closes on itself is one outer ring with one hole; a polygon drawn crossing itself can have one too (ADR-064 decision 3) |
| **Buildable region** | An outer ring with its holes that `core/scene3d.is_buildable_region` accepts: the default builder's own triangulation cuts it and proves the cut. Every region of every scene record is one — the snapshot checks before it hands a record on |
| **Work unit / work budget** | What the 3D pipeline counts instead of timing: every superlinear step between a canvas item and its scene record — counting the pairs of a path, the clipper, sorting rings, cutting a region — has a price in units (about a nanosecond each on the development box) and is paid for out of one budget per item, `core/scene3d/polygon.MAX_REGION_WORK` = 150,000,000, **before it runs**. What the budget does not cover is refused (`outline_too_large`). A count is the same on every machine; a duration is not (§8.32.1, ADR-064 decision 9). |
| **Stack height** | The most edges of an outline that one horizontal line crosses (`core/scene3d/polygon.stack_height`). What a sweep-line clipper pays per step: teeth standing side by side cost it their number squared without crossing anything. One of the three things the clipper's price is made of, beside the vertices and the pairs of edges that cross. |
| **Resolved outline** | What a scene record holds for a polygon drawn crossing or touching itself: not the drawn ring but the regions it fills by the non-zero rule. Marked by `params["outline_resolved"]`; a HOUSE resolved this way carries no ridge. The number of rings is not the mark |
| **Snapshot (3D)** | What `snapshot_records` returns: a plain `dict` of item id → scene record, bottom to top. Items left out because their record could not be built, their id was already taken, their outline cannot be built or one of their lengths is beyond 10 km are reported through the optional `skipped=` list — each a `SkippedItem` with a `SkipReason` code — and one log line each. One bad item never blanks the 3D view, and never vanishes silently |
| **Recording sink** | `core/scene3d.RecordingSink` — the engine sink's test double: records every call, answers what the engine would hold, and raises on a protocol breach. Builders and sync logic are tested against it with no GPU |
| **Scene sync** | `core/scene3d.SceneSync` — applies successive snapshots to an engine sink with the fewest calls: builders only for added items and geometry changes, one transaction or none (records, sun and ground together). Invariant: incremental == full rebuild. A failing sink poisons it; `reset()` recovers through the sink's `clear()` |
| **Plant recipe** | One entry of `core/plant_art/recipes.py` (`SPECIES`, `CATEGORIES`): what a plant looks like, as data — its archetype (`a`), its palette (`pal`) and a few numbers and features. The 2D sprite generator draws the SVG from it and the 3D plant builder builds the silhouette from it, so the plan and the 3D view cannot disagree about a plant's shape or green (ADR-064 addendum, §8.22.4) |
| **Archetype (plant)** | The growth form a plant recipe names with `a=`: `canopy`, `conifer`, `mound`, `climber`, `ground`, `hedge`, `rosette`, `head`, `grass`, `allium`, `feathery`, `flower`, `palm`. One drawing routine per archetype in the sprite generator, one silhouette builder per archetype in 3D (`core/scene3d/builders/plants.py`); a test fails when the two sets differ |
| **Sprite resolution** | `core/plant_art/resolve.resolve_sprite` — the one rule that picks a plant's sprite, and so its recipe, from its object type, species string and plant category: species (exact name, else the first partial match), else category, else the type's default category. Asked by the 2D renderer and the 3D builder alike, on the same three inputs — the species string is the item's own, raw (`item.plant_species`; the record's `sprite_species`), never the species data's name. Its quirks are pinned by a golden of 1,562 answers, whose generator (`scripts/make_sprite_resolution_golden.py`) also holds it to the old rule with sprite files missing |
| **Fit report** | `core/scene3d/builders/plants.FitReport` — what the fit had to repair on a plant builder's output: the builder's own top as a fraction of the height, the scale factors, the share of foliage vertices pulled back onto the canopy circle and how far out they were, the share pressed onto the ground, how far the plant was set down — and where the plant ENDS (`reach`: its farthest vertex from the axis in canopy radii, wood included; for the foliage never more than `REACH_MAX` = 1.09, because the fit's last step holds it there, and for the plant as long as foliage is its outermost part — the trunk builders' invariant) and whether that last step moved anything. The instrument that holds the builders to building TO the data — a bounding box that is exact after the fit says nothing about the plant (§8.32.7). |
| **Shape cache** | The plant builder's memory: a shape is built once per (recipe form, seed, 5 % step of height over canopy radius) and scaled to the plan's exact size, so a plant that grows is a multiplication, not a rebuild. Capped in bytes (`SHAPE_CACHE_BYTES`, 256 MB), not in a count, and without a cliff at the cap: beyond it a date scrub rebuilds only the plants that do not fit; a shape dropped at the cap comes back in two builds, and `clear_shape_cache()` (shapes and request log) on plan close starts the next plan clean (`PROPORTION_STEP`; §8.32.7). |
| **Fit (3D plant)** | The last step of every plant build: foliage centred on the canopy circle, then scaled so the mesh's bounding box is the plan's data — top = resolved height, widest span = canopy diameter, base at 0. The builders build TO those numbers; the fit normalises the last millimetre and reports what it repaired (*Fit report*). Its LAST step puts any FOLIAGE vertex further than 1.09 canopy radii from the axis onto that circle, so where a plant's foliage ends is bounded by construction; wood is not moved and stays inside by the trunk builders' radii (§8.32.7) |
| **Placeholder (3D plant)** | What the 3D view shows for a plant whose height the plan does not know (no species data, no measurement, no typed height): a low, smooth, neutral dome over its canopy circle that casts no shadow — a marker, never a guessed plant. A height turns it into the plant. Common: every category plant from the gallery, every plant drawn with a tool, and any plant whose species string names one of the twelve sprites without a bundled species record (§8.32.7) |
| **Standing base** | How high above the garden floor an item stands, in cm: the soil surface of its parent bed or container when it is linked to that parent AND its centre lies inside the parent's shape, the parent holds soil and has a height — else 0. One rule (`core/object_height.standing_base_cm`, asked through `ui/canvas/footprints.item_base_cm`) for a scene record's `transform.base_cm` and a shadow caster's `base_cm`. An item's height is measured from its base (ADR-037 addendum, §8.32.6) |
| **Soil drop** | The 2 cm assumed between the rim of a BED (raised bed, a garden bed with a height) and its soil (`core/object_height.SOIL_DROP_CM`) — a modelling assumption: the plan holds no fill level for a bed. A plant in a 40 cm raised bed stands at 38 cm. A container has no drop: its height is its soil fill height, so a plant in a 30 cm pot stands at 30 cm. The 3D bed meshes put their soil at the same heights |
| **Standing parent** | The soil parent whose solid a plant stands in: the plant is linked to it, it is visible, it is a bed, raised bed or container WITH a height, and the plant's centre lies inside its shape (`ui/canvas/footprints.standing_parent` — the membership half of the base rule). The per-plant sun estimate spares that parent for the plant, like the plant's own solid: the bed is under the plant, not between it and the sun (ADR-056 addendum) |
| **Shadow caster** | `core/shadow_geometry.ShadowCaster(footprint, height_cm, base_cm)` — one solid of the sun & shade model: its scene footprint, its height above its own ground and the height of that ground. Collected once per recompute by `collect_shadow_casters`; the shadow overlay and the hours-of-sun heatmap consume the same list. The shadow functions accept a `ShadowCaster` or an exact `(footprint, height)` pair and nothing else |
| **Built world** | In the 3D pipeline, everything that is constructed rather than grown: buildings, fences, walls, beds, containers, hedges. Its builders live in `core/scene3d/builders/` (ADR-064 addendum) |
| **Tinted part** | A mesh part whose vertices are pure white and whose colour is the plan item's own (fill, else stroke), multiplied in by the engine sink. Fences, walls, building walls and containers are tinted, so recolouring one never rebuilds its mesh |
| **Live ridge** | A HOUSE's ridge as the canvas has it right now: the end points of its linked `ROOF_RIDGE` item, recomputed by the canvas on every edit of the house (ADR-046) and carried in the house's scene record as `params["ridge"]`. The 3D roof is built from it and never derives one |
| **Fit scale** | Resolved height divided by the top of what a builder built. 1.0 means the builder was exact; the built-world builders are, by construction, and a test asserts it (§8.32.6) |
| **Plain panel** | What a fence or wall line is built as in 3D when its style is one no builder knows (a path style, a fence style added later): the stroke as wide as it is drawn, up to the height — the same solid the 2D shadow model casts. Never another style's look (`core/scene3d/builders/lines.py`) |
| **Bed membership point** | The scene point the LINK decisions ask — which bed is an item linked to: the centre of its `boundingRect()` (`ui/canvas/footprints.bed_membership_point`). Auto-parenting (create, bulk create, paste), the re-link after a drag, the agent's re-link after a move and its `link_is_geometric` ask this point. It moves by up to 1.8 cm along each axis (about 2.5 cm diagonally) while a plant shows its antagonist badge; where an item STANDS is asked of the standing point instead |
| **Standing point** | The scene point that decides whether a linked item stands on its parent's soil: its stable geometric centre (`ui/canvas/footprints.standing_point`) — the anchor of its outline, a plant circle's centre, the origin of its 3D record. It changes only with the item's geometry or pose, never with a badge or highlight. Tested with the same containment predicate as the bed membership point (`shape_contains`) |
| **Engine package** | `ui/view3d/quick3d/` (Phase 17 L1.2) — the one package that imports Qt Quick 3D: `Quick3DSink` (the engine sink), `Quick3DHost` (the `QQuickView`), the offscreen render path, `Garden.qml` and its shaders. Its engine-free modules are covered by the GPU-less test run |
| **Engine host** | `quick3d.host.Quick3DHost` — the Qt Quick window that shows the garden and owns every engine Model. Kept alive and hidden / shown, never rebuilt per open; embedded with `container()` (a window container, never a `QQuickWidget`) |
| **Host state** | Where an engine host is in its life — new, starting, live, hidden, spent or closed — a pure function of facts the host reads from Qt on every call (`quick3d.lifecycle.state_of`), never of a flag. It decides which call is legal; whether a frame has the window's size is said by the frame itself, which the host checks each time it takes one. The contract — the facts, the states, the legal calls, what `wait_ready()` means — is the module docstring of `ui/view3d/quick3d/lifecycle.py` and is written down nowhere else (§8.32.2; why each fact is there: §11.4.32) |
| **Host health** | `Quick3DHost.health()` → `HostHealth`: what Qt reported about a shown engine host on the GUI thread — QML warnings, a graphics device that could not be created, frames presented. A poll surface; there is deliberately no Qt message recorder for a shown view (§8.32.2) |
| **Supervised watchdog** | `runlog.watchdog(…, supervised=True)`: the in-process watchdog (stack dump, exit code 1) plus a second process that terminates the first from outside when it is still alive ten seconds after the deadline. On Windows the in-process exit does not end a process deadlocked inside Qt. In the frozen build the second process is the exe itself, started with the internal flag `--selftest-supervisor`. It acts for one block of its own parent process and for nothing else, one watchdog is armed per process at a time, and on Windows the self-test fails without it (§11.4.32) |
| **Frozen gate** | The two checks every merge owes the frozen exe: the 8-second smoke and `--selftest` (`ogp-change-control` §2.8). Run locally before a merge, by `frozen-selftest.yml` on pull requests that change shipped code, and by `release.yml` after the merge. The self-test is the gate; the smoke only proves that the process starts |
| **Part (engine)** | One engine `Model` for one mesh part of an item, with its own geometry and material instance. Created by `add`, destroyed by `remove`; a geometry lives exactly as long as its Model |
| **Shot** | A camera placement as plain data in scene coordinates: `PerspectiveShot` (eye, target, field of view) or `TopDownShot` (centre, pixels per centimetre) |
| **Truth view** | The top-down orthographic shot, north up and NOT tone-mapped: a pixel is linear radiance, and where a point lands is plain arithmetic (`shots.top_down_pixel`). What the render tier predicts and measures in |
| **Look** | `quick3d.look.Look` — everything about a frame that is art direction and not truth (sun colour and brightness, fill, exposure, sky colour, meadow albedo). L1.2 has one, `NEUTRAL_DAY`; where the sun stands is never part of a look |
| **Ground bake** | Painting the plan's flat surfaces — everything with a paint description and no 3D solid — into ground tiles from the snapshot's records, as the 2D canvas paints them (`ui/view3d/ground_bake.GroundBaker`, Phase 17 L1.5). Never a render of the live scene: no selection, visibility or `scene.changed` is touched. §8.32.5. |
| **Ground tile** | One 512-px piece of the baked ground: its rectangle in scene centimetres and its RGBA8 pixels, row 0 on the north edge (`core.scene3d.GroundTile`). Every tile is a crop of ONE pixel grid over the plan (`GroundGrid`), so tiles meet without a seam; an edit re-bakes only the tiles it touches, and an untouched tile is the same object as before. |
| **Paint description** | What a scene record carries so that the ground bake can paint its item as the canvas does: `Material.paint` (`Paint`: pen width, style, cap, join, opacity), the anchor of the record's local frame in item coordinates (`params["paint_origin"]`) and, where the regions are not the drawn polygon, `Record.outline`. Every item but a plant has one. |
| **Tile budget (walk budget)** | What everything painted into ONE ground tile may cost together: 16,384 path-style elements, 16,384 steps of the walk that finds them, 32,768 dashes (`path_style_paint.WalkBudget`, `ground_bake.tile_budget`), beside the tile's 256 records and 262,144 outline-vertex passes. A spent budget means "no more"; the tile is then listed in `GroundBaker.capped`. Not the bake budget: these bound COUNTS in one tile, that one the time of one call. |
| **Bake budget** | The time one call of the ground bake spends painting tiles: `BAKE_BUDGET_S`, 10 ms, read from an injectable clock after each tile. A call paints at least one tile; it costs at most the budget plus the tile it is in — plus one tile of the backlog when it brings an edit while older tiles are pending. §8.32.5. |
| **Pending tile** | A ground tile the bake budget did not reach: it still shows its older picture (bare ground when the plan was just opened) and is handed out as the object it was. `GroundBaker.pending` counts them, `SceneSync.ground_pending` says that there are some, `SceneSync.continue_ground()` paints on — nearest to the last edit first. Once none is pending the ground is the ground of one complete bake. |
| **Cover (of a ground tile)** | A record whose fill covers the WHOLE tile. An opaque cover ends the tile's admission walk — nothing under it is looked at or painted. |
| **Member (of a ground tile)** | A record whose paint reaches the tile and that no opaque cover above it hides. A tile keeps all its members up to its bounds; beyond them it keeps the ones whose paint box overlaps it most (ties to the topmost) and loses its smallest (`GroundBaker._admit`). |
| **Capped tile** | A ground tile painted with a bound in force: it holds less than the plan — its smallest members, a style's elements or its dashes (`GroundBaker.capped`). |
| **Backlog (ground bake)** | The pending tiles a call did not make dirty itself. A call that brings an edit paints one of them in addition to the edit's own tiles, so an edit a pass cannot starve them. |
| **Parked tile** | A ground tile whose paint raised as a whole: it keeps the picture it had, is listed in `GroundBaker.tile_failures`, is not pending, and is tried again by the next call that brings a change. |
| **Restart (of a ground baker)** | `GroundBaking.restart()`: forget what the tiles were painted with, keep their pictures until each is painted anew. What `SceneSync` does to a baker whose `bake` raised — `clear()`, which forgets the pictures too, is for a new plan. |
| **Paint turn** | The rotation of a circle's own coordinates, which its record's transform does not carry (a circle's footprint and solid do not turn): `Paint.rotation_deg`. What is painted IN the circle — texture, dashes, sprite — turns with it; a material change. |
| **Style attributes (of an item)** | `fill_color`, `fill_pattern`, `stroke_color`, `stroke_width`, `stroke_style`: what an item says about its look to the project file, the clipboard, the properties panel and the 3D snapshot — beside the live brush and pen the canvas paints with. Kept in step by `core/item_look.py`, the one writer; held to it by a teardown fixture over every integration test. An item whose picture is a sprite (`paints_sprite`) is exempt: neither its brush nor its pen paints its picture. |
| **Keep-alive rule (ground textures)** | Per ground tile the engine side holds exactly the texture the scene shows, plus — until the next presented frame, at the latest the next update — the one it replaced (`quick3d/ground_tiles.py`). `ground_tiles.textures_alive()` counts the objects that exist on the C++ side. The L0 spike's append-only list grew by one ground per reload. |
| **Render tier** | The opt-in tests that need a real renderer (`OGP_RENDER3D=1`): a driver process with a real Qt platform renders, the tests judge its frames with a CPU projection of their own. Runs on a GPU, on WARP and on llvmpipe (CI job `render3d`) |
| **WARP** | Windows Advanced Rasterization Platform — Direct3D's software rasteriser (Qt's log names it "Microsoft Basic Render Driver"). What a GPU-less Windows runner renders with; forced locally with `QSG_RHI_PREFER_SOFTWARE_RENDERER=1` |
| **Workspace (3D)** | `ui/view3d/workspace.Workspace` — the plan area of the main window with its three **workspace modes**: Plan (the canvas alone), 3D (the 3D pane alone), Split (both in a splitter whose sides do not collapse). Behind `OGP_QUICK3D=1` until L1.9 (Phase 17 L1.3, ADR-065, §8.32.3) |
| **3D pane** | The workspace's 3D side: a strip of controls and notices above the engine's native window — or a message in its place. Nothing ever overlays the native window (§8.9.9) |
| **Sync controller** | `ui/view3d/sync_controller.Scene3DController` — turns the canvas scene's and the sim clock's change signals into at most one **pass** per turn of the event loop: snapshot → `SceneSync.apply`. Paused (flags only) while the 3D pane is hidden (ADR-065) |
| **Plan revision** | `CanvasScene.plan_revision` — one integer that moves exactly when the plan's CONTENT changed (an item added, removed, moved, turned, shown, hidden, restacked; a command executed, undone or redone; a layer; the canvas size), announced by `plan_changed(int)`. A writer that changes plan content round all of those calls THE nudge, `CanvasScene.note_plan_changed()`. A repaint does not move it (ADR-065 decision 5) |
| **The net (quiet-time reconciliation)** | The 3D sync controller's second layer: a repaint that no plan-revision move explains starts nothing but ONE quiet timer (400 ms); when the scene has been still that long one pass reconciles 3D with the plan. It normally finds nothing; what it finds is an edit path that forgot its announcement, counted in `unannounced_changes` (ADR-065 decision 5) |
| **Pass (3D pipeline)** | One run of snapshot and apply, started by a posted event; a time-of-day change is a light-only pass without a snapshot. Reported as a `TickReport` |
| **Catch-up pass** | The one pass that runs when the 3D pane becomes visible with changes owed; a plain apply of the current snapshot, equal to a from-scratch apply. It starts after its "building" notice was painted |
| **Readback (3D)** | A frame rendered for reading its pixels (`Quick3DHost.grab()`; `wait_ready()`, `pick()` and `project()` need one too). It is never presented, and what it holds comes back only when a presented frame ends — so nothing takes one from the live, shown view by itself; pictures for files go through the offscreen host (ADR-065 decision 17) |
| **Retired item** | An item whose engine Models a pass destroyed — removed, its geometry replaced, or cleared by a reset (`TickReport.retired`). Qt keeps graphics state for every Model it once drew; the workspace counts retired items to know when to release it (ADR-065 decision 15) |
| **Orbit camera** | `core/scene3d/camera.OrbitCamera` — the session's one 3D camera as a Qt-free value: a goal pose and a critically damped pose that follows it. Moved only by user input, "Reset 3D View", the first open and a document change — never by an edit |
| **Start marker / start guard** | `ui/view3d/init_guard.Init3DGuard` — a per-process file written before the first 3D window of a session is built and removed after its first presented frame. A marker left by a process that is gone means the graphics driver took the process down (ADR-065 decision 10) |
| **Compatibility mode (3D)** | 3D rendered on the software adapter (WARP on Windows) for this window, after a start that died or at the user's request; shown as a notice in the 3D pane with "Try Hardware Next Time". Only the user switches back |
| **Engine factory** | `Workspace.engine_factory(prefer_software) -> (host, sink)` — what builds the engine on first use, and the seam at which the GPU-less tests put a recording sink and a stand-in host |
| **Workspace gate** | `tests/integration/workspace_gate_hook.py` — test tooling that runs a scripted scenario inside the real app (from source, or as a runtime hook of the **gate build**, `installer/workspace_gate.spec`) on a throw-away settings store, and ends the process before a store under any other organisation exists (§8.10.27) |
| **Presented frame** | A frame Qt rendered AND handed to the window system — as opposed to a readback (`grabWindow()`). Qt Quick 3D frees a destroyed Model's buffers only at the end of a presented frame; with the display asleep Windows presents none (§11.4.33) |
| **Light probe (IBL)** | An environment image (here the procedural sky) that lights a Qt Quick 3D scene from all directions — image-based lighting. Pre-filtered once per texture object, so a sun change builds a new one; costly on software rasterisers (ADR-048 evidence) |
| **Canopy Diameter** | The spread/width of a tree or shrub's foliage when viewed from above |
| **Amendment** | Soil-improving substance (lime, blood meal, compost, etc.) loaded from `resources/data/amendments.json`. Carries application rate (g/m²) and per-fix effect coefficients used by the calculator |
| **Bundled Species DB** | Curated `resources/data/plant_species.json` shipped with the app (~120 records covering every gallery thumbnail, full pH/NPK/sun/water/calendar fields per species). Looked up on canvas drop and tool draw by scientific name → common name → alias to auto-populate `metadata["plant_species"]`; the long tail still falls through to the on-demand API search (issue #170) |
| **AmendmentRecommendation** | Calculator output for one substance applied to one bed: amendment + grams + rationale (e.g. "Raises pH 5.8 → 6.5") |
| **Calibration** | The process of marking a known distance on an image to establish metric scale |
| **Command Pattern** | Design pattern where every modification is wrapped in an object with execute/undo methods |

Both soil generators emit `soil`, so the amendment and mismatch tasks are told apart by **task type** (`soil_amendment` vs `soil_mismatch`) — filtering by source alone cannot select one. An unknown source is refused, not ignored. See §8.19 |
| **Task type** | The stable English key for the *kind of work* a task is (`direct_sow`, `harvest`, `soil_amendment`, `soil_mismatch`, …). This is the field an agent branches on — not `source`, and never `title`, which is display text in the user's UI language. See §8.19 |
| **Urgency** | A render-time bucket for a task window, computed from its dates and "today" rather than stored: `today`, `overdue` (1–14 days past), `this_week` (starts in 1–7 days), `upcoming`, or null when not actionable. Computed by `task_generator.classify_urgency`, which the Tasks tab and the agent both call — never re-implemented. |
| **Coverage marker** | The field that says what an answer is *based on*, so a thin result is never mistaken for a clean one: `no_frost_dates` (no geo-location, so calendar and propagation tasks could not be generated), `no_soil_test` (**untested**, never "healthy"), `no_beds`, `full`. Present even when the task or recommendation list is empty — an empty list alone would read as "nothing to do". See §8.19 |
| **Rapitest scale** | The categorical soil-test scale: nitrogen and phosphorus `0–4`, potassium **`1–4`** (the kit has no zero for K), and the Ca/Mg/S secondaries `0–2`. Distinct from the optional lab `*_ppm` floats, which nothing in `services/` reads and for which no conversion exists (US-12.10c) — which is why the agent's `record_soil_test` takes the kit scale only. See ADR-036 addendum |
| **Effective soil record** | The test that applies to a bed, resolved by a documented hierarchy: the bed's own latest, else the plan-wide default's latest, else none. `SoilService.get_effective_record` returns the record alone, so the Agent API also reports **`record_source`** (`bed` / `global` / `none`) — without it a plan-wide assumption reads as a measurement of that bed. See §8.19 |
